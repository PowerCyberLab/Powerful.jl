Core: Types and Variables (PowerfulCore)

Model supertype, variable and residual declarations and address spaces shared by every model and solver. Metadata and traits are on Metadata and Traits; per-unit kinds are on Formulations, Units and Registry. These names are defined in PowerfulCore.Foundation and exported by PowerfulCore.

Modules

PowerfulCore.PowerfulCore — Module

PowerfulCore - Foundation module for power systems simulation

This package provides the core type system, DAE infrastructure, and system utilities that form the foundation of the Powerful ecosystem.

Contents

  • Foundation: Core types (AbstractModel, ModelVar, ModelResidual, etc.)
  • DAEInfra: Address management, gather/scatter, residual workspaces
  • System: SystemBuffers, per-unit conversion, topology analysis
  • Registry: Model registration system

Usage

using PowerfulCore

# Access core types
abstract type MyModel <: AbstractModel end

# Use address management
am = AddressManager()
assign_address!(am, :MyModel, :x, AlgebVar, 5)

# Use DAE vectors
dae = DAE(Float64, Vector, 10, 5)

PowerfulCore.Foundation.VIRTUAL_BUS_BASE — Constant

Base number for virtual buses created from 3-winding transformer conversions. Virtual buses are numbered VIRTUALBUSBASE + 1, VIRTUALBUSBASE + 2, ... This avoids conflicts with real power system bus numbers (typically < 100,000).

PowerfulCore.Foundation.AMDAddressing — Type
AMDAddressing()

Approximate minimum degree (AMD) reordering of the algebraic addresses, computed from the Jacobian sparsity pattern when the problem is built. The permutation it applied is recorded in the problem's AddressManager as applied_permutation; to reuse a known ordering, pass it as CustomPermutation.

Example

prob = ACPowerFlowProblem(sys; addressing=AMDAddressing())
perm = prob.address_manager.applied_permutation

PowerfulCore.Foundation.AbstractModel — Type
AbstractModel

Supertype of every model struct (buses, branches, loads, generators, controllers).

A model type describes a single device instance; a system stores all instances of one model as a StructArray. Behavior is attached through traits such as model_metadata, calc_residuals!, get_terminals and get_key_name, and the type is made known to the system with @register_model.

PowerfulCore.Foundation.AddressManager — Type

Enhanced address manager with explicit address assignment tracking

Fields

  • addresses: Maps (AddressableType, modelname, variablename) → address vector
  • next_idx: Tracks next available address for each AddressableType
  • assignments: Tracks assigned addresses per model (internal variables)
  • retrieved: Tracks retrieved addresses per model (external variables)
  • reverse_map: Reverse lookup (address → model/var metadata), built during setup
  • strategy: Address reordering strategy (NaturalAddressing, AMDAddressing, etc.)
  • applied_permutation: Permutation the strategy applied to the algebraic addresses (new address k holds natural address perm[k]), or nothing for natural order

PowerfulCore.Foundation.AddressingStrategy — Type

Address reordering strategies for sparse factorization optimization.

System-level address reordering can improve sparse matrix factorization performance by reducing fill-in and improving cache locality.

Available Strategies

  • NaturalAddressing: Sequential addressing in model order (default)
  • AMDAddressing: Approximate Minimum Degree ordering for minimal fill-in

Custom address reordering using a user-provided permutation vector.

PowerfulCore.Foundation.Disturbance — Type
Disturbance

Abstract base type for all TDS disturbance events.

Disturbance events are discrete changes applied during time-domain simulation, such as faults, trips, load changes, or setpoint modifications.

Concrete types:

  • FieldModification: Universal primitive for modifying model fields
  • Event types that also reset states (e.g. a fault clearing that zeroes fault currents)

Each concrete type must implement a to_callback() method to integrate with DifferentialEquations.jl.

PowerfulCore.Foundation.ExtParam — Type
ExtParam

Declares how to retrieve external parameters from other models.

ExtParam uses Terminal as base type to avoid duplicating connectivity information. Terminal specifies WHAT vertex is referenced, ExtParam adds WHICH FIELD to fetch from that vertex.

Fields

  • name::Symbol: Local parameter name in this model (e.g., :i_basekv, :basekv)
  • terminal::Terminal: Vertex connection (contains vertex_model and field)
  • ref_field::Symbol: Field to retrieve from the referenced vertex (e.g., :basekv, :ide)
  • ref_type::ReferenceType: Type of reference (BaseVoltage, BasePower, etc.)
  • phase::RetrievalPhase: When to retrieve (PrePerUnit or PostPerUnit)
  • required::Bool: Whether this reference is required
  • description::String: Human-readable description

Examples

# Branch: Get base voltage from buses at both terminals
const BRANCH_TERMINALS = (Terminal(:Bus, :i), Terminal(:Bus, :j))

const BRANCH_EXT_PARAMS = [
    ExtParam(:i_basekv, BRANCH_TERMINALS[1], :basekv, BaseVoltage(), PrePerUnit(),
             required=true, description="Base voltage at bus i"),
    ExtParam(:j_basekv, BRANCH_TERMINALS[2], :basekv, BaseVoltage(), PrePerUnit(),
             required=true, description="Base voltage at bus j"),
    ExtParam(:i_ide, BRANCH_TERMINALS[1], :ide, Dimensionless(), PrePerUnit(),
             required=true, description="Bus type at bus i")
]

# PQ Load: Get voltage from single attached bus
const PQ_TERMINALS = (Terminal(:Bus, :i),)

const PQ_EXT_PARAMS = [
    ExtParam(:basekv, PV_TERMINALS[1], :basekv, BaseVoltage(), PrePerUnit(),
             required=true, description="Connected bus base voltage")
]

PowerfulCore.Foundation.GroupLinkRef — Type
GroupLinkRef

References to targets that may be heterogeneous (different model types).

Used for both:

  1. Control links: Controllers (TGOV1) → targets in a group (:generators)
  2. Terminal links: Models → bus-like targets in :bus_group

Each instance can reference a different target model type, enabling polymorphic connections (e.g., TGOV1[1] → GENCLS, TGOV1[2] → GENROU).

Fields

  • target_type::Vector{Symbol}: Target model types for each instance
  • target_idx::Vector{Int}: Target indices within each model type's array

Example

# PQ[1] → Bus[1], PQ[2] → Bus[2], PQ[3] → Bus[3] (homogeneous)
ref = GroupLinkRef([:Bus, :Bus, :Bus], [1, 2, 3])

# TGOV1[1] → GENCLS[5], TGOV1[2] → GENROU[1] (heterogeneous)
ref = GroupLinkRef([:GENCLS, :GENROU], [5, 1])

# Access: get target for instance 2
target_model = ref.target_type[2]  # → :GENROU
target_idx = ref.target_idx[2]     # → 1

PowerfulCore.Foundation.IndexOrder — Type
IndexOrder

Stores external-to-internal index mappings following MATPOWER's ext2int/int2ext pattern.

This structure is created during the ext2int preprocessing stage and stored in SystemModel. It enables fast lookups from external bus numbers (and composite keys) to internal array indices.

Fields

  • key_indices::Dict{Symbol, Dict}: Model instance lookup tables

    • Key: Model name (:Bus, :PQ, :PV, ...)
    • Value: Dict mapping composite key tuple → internal array index
    • Example: key_indices[:Bus][(69953,)] → 67900 (bus number → array index)
    • Example: key_indices[:PQ][(101, "1")] → 5 (bus number, load id → array index)

  • foreign_refs::Dict{Symbol, Dict{GroupRefKey, GroupLinkRef}}: Pre-computed group references

    • Outer key: Referencing model name (:PQ, :Branch, :TGOV1, ...)
    • Inner key: Field/handle for the reference (e.g., :i, :j, or composite key tuple)
    • Value: GroupLinkRef with target types and indices (supports heterogeneous targets)
    • Example: foreign_refs[:PQ][:i] → GroupLinkRef([:Bus, :Bus, :Bus], [1, 2, 3])
    • Example: foreign_refs[:Branch][:i] → GroupLinkRef(:Bus, [5, 7, 9]) # from-buses
    • Example: foreign_refs[:TGOV1][(:BUS, :ID)] → GroupLinkRef([:GENCLS, :GENROU], [1, 1])

Purpose

All models store external bus numbers (semantic meaning preserved), but computation requires internal array indices. This structure provides O(1) lookup via pre-computed indexer vectors, avoiding Dict lookups in hot paths.

See Also

  • ext2int: Builds this structure from parsed models
  • int2ext: Future function to convert results back to external numbering

PowerfulCore.Foundation.InitInput — Type
InitInput

Declares an input required for dynamic model initialization.

Supports three input kinds:

  1. :from_observation: Computed value from linked power flow model (e.g., P, Q from PV/Slack)
  2. :from_solution: Direct variable from DAE solution (e.g., V, θ from Bus)
  3. :fromgroupinit: State from any model in a group (polymorphic - e.g., P_m from :generators group)

Fields

  • name::Symbol: Local name in initialization context (e.g., :Pgen, :Vbus)
  • kind::Symbol: Input kind - :fromobservation, :fromsolution, or :fromgroupinit
  • from_model::Symbol: Source model type or GROUP name (e.g., :Generator, :Bus, or :generators)
  • field::Symbol: Field/variable name in source (canonical group name for :fromgroupinit)
  • description::String: Human-readable description

Examples

# GENCLS needs P and Q from linked PV/Slack generators
InitInput(:P_gen, :from_observation, :Generator, :p_gen;
    description="Active power from linked generator")

# Bus voltage and angle from DAE solution
InitInput(:V_bus, :from_solution, :Bus, :v;
    description="Bus voltage magnitude")

# TGOV1 uses group reference for polymorphism (works with GENCLS, GENROU, etc.)
InitInput(:tm0, :from_group_init, :generators, :P_m;
    description="Mechanical power from any generator in group")

PowerfulCore.Foundation.InitParam — Type
InitParam(name::Symbol, source_var::Symbol; description::String="")
InitParam(name::Symbol; description::String="")

Metadata for initialized parameters (setpoints/constants computed during initialization).

These are constant values computed once during initialization and stored in sys.init_params. They are used by models for holding equations (when no controller is present) or as references.

Two-argument form: Variable → Setpoint copy

Use when copying a variable's initial value to a differently-named setpoint:

InitParam(:P_m0, :P_m; description="Mechanical power setpoint")
# Copies initial value of variable :P_m to setpoint :P_m0

One-argument form: Computed setpoint

Use when the setpoint is computed directly in initialization (not copied from a variable):

InitParam(:pfaref0; description="Initial power factor angle")
# Setpoint :pfaref0 is provided directly by initialize_dynamic_states

Storage

Values are stored in sys.init_params[:ModelName].param_name as vectors.

Usage

Models access these via ws.setpoints.P_m0[i] in residual calculations.

PowerfulCore.Foundation.InjectionForms — Type
InjectionForms(natural; power, current, voltage = Symbol[])

The forms of the injection a model delivers to the bus group of a terminal: the residuals that carry its power (p, q), those that carry its current (ip, iq: in phase with and in quadrature to the bus voltage, positive into the bus; p = v ip, q = v iq), and, for a model that is an electromotive force E behind an impedance Z (a machine behind its subtransient reactance), those that carry its short-circuit current (jr, ji: J = E/Z on the system base, real and imaginary parts in the network frame), voltage. The model declares one form (natural, :power, :current or :voltage) and computes the others from it; a connection is delivered through exactly one of them (injection_routes): the declared form where the bus implements it, otherwise, for :voltage, the current form and then the power form, and for the other two the other one.

The voltage form is realized by the bus. A bus that implements it (a bridging device) gives the model the voltage behind which its delivered current I flows, Vport = E - Z I (the group variables `vport,thetaport`), so the model's current (E - Vport)/Z is the current the network receives; every other bus gives V_port = V, the bus voltage, which realizes the same form algebraically, I = (E - V)/Z.

LinkedDevice()

PowerfulCore.Foundation.MassCoefficient — Type
MassCoefficient{F}

Mass coefficient property for differential state variables in DAE systems. Specifies how to obtain the mass coefficient that multiplies the time derivative: M*dx/dt = f(x).

Type Parameter

  • F: Either Symbol (field lookup) or a Function type (computed value)

Field

  • source::F: Source of mass coefficient values - either:
    • Symbol: Field name in model struct (e.g., :M) for direct lookup
    • Function: Callable f(models) -> Vector that computes mass values from model data

Constructors

MassCoefficient(:M)                    # Field lookup: models.M
MassCoefficient(m -> 2.0 .* m.H)       # Function: compute M = 2H inline

Usage in ModelVar

# Direct field lookup (backward compatible)
ModelVar(:omega, StateVar(); mass_coefficient=:M, ...)

# Function-based (AD-compatible, for derived coefficients)
ModelVar(:omega, StateVar(); mass_coefficient=MassCoefficient(m -> 2.0 .* m.H), ...)

AD Compatibility

Function-based mass coefficients are fully AD-compatible. When model parameters are Dual numbers (during Jacobian computation), the function receives Dual arrays and returns Duals, preserving gradient information. Example: ∂M/∂H = 2.0 flows through m -> 2.0 .* m.H.

See Also

  • eval_mass_coeff: Type-stable extraction of mass values
  • get_mass_coeff: Retrieve MassCoefficient from ModelVar

PowerfulCore.Foundation.ModelLinks — Type
ModelLinks

Struct-of-arrays for linking dynamic models to power flow models.

Used in time-domain simulation to map DYR file models (GENCLS, GENROU, etc.) to their corresponding power flow models (PV, Slack).

Fields

  • source_type::Vector{Symbol} - Dynamic model types (e.g., [:GENCLS, :GENCLS, ...])
  • source_idx::Vector{Int} - Indices in dynamic model arrays
  • target_type::Vector{Symbol} - Static model types (e.g., [:PV, :Slack, :PV, ...])
  • target_idx::Vector{Int} - Indices in static model arrays

Example

links = ModelLinks(
    [:GENCLS, :GENCLS, :GENROU],
    [1, 2, 1],
    [:PV, :Slack, :PV],
    [3, 1, 5]

# GENCLS[1] → PV[3], GENCLS[2] → Slack[1], GENROU[1] → PV[5]

mask = links.source_type .== :GENCLS
target_types = links.target_type[mask]
target_indices = links.target_idx[mask]

PowerfulCore.Foundation.ModelMetadata — Type
ModelMetadata

Complete metadata for a power system model.

Formulation Support

Models can support multiple formulations (PowerInjection, CurrentInjection). The vars and residuals fields define the default formulation (PowerInjection). Alternative formulations can override these via vars_by_formulation and residuals_by_formulation.

Automata

automata and memory declare the discrete behaviour of the model (see Automaton and MemoryQuantity), as tuples; both are empty for a model without it. A model that declares automata computes the values they name in calc_automaton_values!, and its residual kernels read the discrete quantities and memory of its workspace (ws.automata.discrete, ws.automata.memory, see AutomatonState).

Example

function model_metadata(::Type{Branch})
    base = ModelMetadata(
        name = :Branch,
        vars = BRANCH_VARS,  # PowerInjection variables (θ, V)
        residuals = BRANCH_RESIDUALS,  # Power balance
        # ...
    )

    # Add CurrentInjection support
    base.vars_by_formulation[CurrentInjection] = BRANCH_VARS_CURRENT  # (Vr, Vi)
    base.residuals_by_formulation[CurrentInjection] = BRANCH_RESIDUALS_CURRENT  # Current balance

    return base
end

PowerfulCore.Foundation.RatingRatio — Type
RatingRatio(name, NominalPower; description = "")

Declares a derived parameter of a model: name is the ratio of the model's resolved power rating Sn (its ModelRating, from its own field or from the device it replaces, LinkedDevice) to the system base Sb, Sn/Sb. It is not a field of the model and has no DYR entry; Powerful computes it with the per-unit coefficients (calc_pu_coefficients, which keeps it in sys.pu_coeffs[model][name]) and the kernels read it as external.name[i] (the external parameters of the model), and initialization as gather_init_data(ctx, M).name.

A model that declares it multiplies by it the quantities it holds on its own (device) base where they enter the network, which is on the system base: a power or a current into the bus is ratio times the device-base value, and the system-base power read from the network is divided by it. The model must declare a NominalPower rating (a derived ratio without one is an error, not a ratio of 1).

PowerfulCore.Foundation.SharedRes — Type
SharedRes(mode::Symbol = :add)

Residual access pattern for shared address space (e.g., bus power balance).

Modes

  • :add - Accumulate with += (default). Used for power balance contributions.
  • :set - Overwrite with =. Used for control equations (e.g., PV voltage control). Applied AFTER all :add modes to replace accumulated values.

Examples

SharedRes()        # Default :add mode for power balance
SharedRes(:add)    # Explicit :add mode
SharedRes(:set)    # Setter mode for control equations

Mutability

Made mutable to support observation mode where SharedRes(:set) is temporarily changed to SharedRes(:add) to extract generator power contributions.

PowerfulCore.Foundation.SystemModel — Type
SystemModel

Power system network model containing all components (buses, branches, loads, generators, etc.).

A pure data container storing per-unit models and index mappings. Formulation-specific infrastructure (AddressManager, DAE vectors) is created at problem construction time, not stored here.

Fields

  • models::NamedTuple: A named tuple of models (per-unit for computation)

  • external::NamedTuple: External parameters retrieved from other models (topology-derived references)

  • order::Union{Nothing, IndexOrder}: Index mappings for external-to-internal conversion (MATPOWER ext2int pattern)

  • array_type::Type{<:AbstractVector}: Array type for computational backend (Vector for CPU, CuVector for GPU)

  • parsed_data::Any: Optional: original parsed data in physical units (from ParsedSystemData)

  • pu_coeffs::Union{Nothing, NamedTuple}: Optional: per-unit conversion coefficients for inverse conversion (pu → physical)

  • topology::Any: Optional: cached topology analysis results (connectivity, islands)

  • settings::SystemConfig{Float64}: System-wide settings (frequency and MVA base) used by every analysis of the system

Constructors

SystemModel(case::ParsedSystemData)      # From parsed RAW file
SystemModel(components::NamedTuple)      # Direct from model StructArrays

Example

using Powerful, PowerfulCases

# Load and parse a case file
case = parse_network(load("ieee14").raw)
sys = SystemModel(case)

# Access models
sys.models.Bus      # StructArray of all buses
sys.models.PQ       # StructArray of PQ loads
sys.models.Branch   # StructArray of branches

# Check system size
length(sys.models.Bus)  # Number of buses

# Create problem and solve
prob = ACPowerFlowProblem(sys)
sol = solve(prob, Newton())

See Also

PowerfulCore.Foundation.Terminal — Type
Terminal

Declares that a model field references a vertex (Bus, Node, etc.) or another model in the network graph.

Used for both topology analysis and external parameter retrieval (ExtParam). This is the single source of truth for model connectivity.

Fields

  • vertex_model::Symbol: Target model type (:Bus, :Node, :GENCLS, etc.) or group (:bus_group, :generators)
  • ref_key::Union{Symbol, Vector{Symbol}}: Field name(s) in this model used to look up the target
    • Single field: :i (simple key like bus number)
    • Composite key: [:BUS, :ID] (for matching dynamic models)

Examples

# Branch connects two buses (single-field keys)
Terminal(:Bus, :i)  # "from" bus at field :i
Terminal(:Bus, :j)  # "to" bus at field :j

# TGOV1 controls a generator (composite key)
Terminal(:generators, [:BUS, :ID])  # Match by bus number + machine ID

PowerfulCore.Foundation.VariableLimit — Type
VariableLimit(variable, lower, upper; when = nothing)

The bounds of a model variable, declared apart from how they are enforced: by an automaton that holds the variable at them (anti-windup lowered to an automaton), see variable_limits. Each bound is nothing (no bound at that end), the name of a model field, or a function of the model arrays computing it for every instance (or one number for all), as a MassCoefficient is; a function of two arguments, the model arrays and the model's initialized variables (a NamedTuple of the variables' initial values), computes a bound that depends on the operating point. The initialization checks the initial value of the variable against them, and moves a violated bound that is a field to it (enforce_initial_limits!, TDSConfig(adjust_limits)); a computed bound cannot be moved, and its violation is an error.

when (a function of the model arrays and the model's initialized variables, as a bound of two arguments is, computing for every instance whether the limit applies: a Bool vector or one Bool) restricts the check to the instances where it holds: a variable that equals what the limits bound only under some flags or operating points (a reference that is the reactive power only where a controller acts on it). nothing applies it everywhere. Where a bound is moved to the initial value the start is computed again from the moved data (enforce_initial_limits!).

Example

VariableLimit(:LAG_y, :Vmin, :Vmax)
VariableLimit(:LAG_y, :Vmin, m -> 2 .* m.Vmax)
VariableLimit(:PI_xi, (m, initial) -> .-initial.Imax, (m, initial) -> initial.Imax)  # bounds read from the initialized Imax
VariableLimit(:Qref, :QMin, :QMax; when = (m, x) -> m.VFLAG .== 1)                   # only where VFLAG = 1

PowerfulCore.Foundation.eval_mass_coeff — Method
eval_mass_coeff(mc::MassCoefficient, models) -> AbstractVector

Type-stable dispatch for extracting mass values from a MassCoefficient. Uses compile-time dispatch on F type parameter instead of runtime isa checks.

Arguments

  • mc::MassCoefficient{F}: Mass coefficient specification
  • models: StructArray of model instances

Returns

AbstractVector{T} of mass coefficient values, one per model instance. When models contains Dual numbers, returns Dual vector (AD-compatible).

Methods

  • MassCoefficient{Symbol}: Returns getproperty(models, mc.source) (field lookup)
  • MassCoefficient{<:Function}: Returns mc.source(models) (function call)

Example

models = StructArray(; H=[5.0, 10.0], D=[1.0, 1.0])

# Symbol-based: direct field access
mc1 = MassCoefficient(:H)
eval_mass_coeff(mc1, models)  # [5.0, 10.0]

# Function-based: computed value
mc2 = MassCoefficient(m -> 2.0 .* m.H)
eval_mass_coeff(mc2, models)  # [10.0, 20.0]
