Network bus data records.

Fields

  • evlo::Any: Emergency voltage magnitude low limit in pu.

PowerfulPF.bus_residual_kernel! — Method
bus_residual_kernel!(outputs, params, vars, ide, ::Type{AT})

Pure computation kernel for Bus residuals.

Bus model is purely passive - all residuals are zero for all bus types. The Bus model only provides the shared residual buffers (p, q) that other models contribute to:

  • Branch models add power flow contributions
  • PQ load models add consumption
  • PV generator models add generation and handle slack bus constraints

Note: Slack bus equations (θ = θref, V = Vref) are implemented in the PV model, NOT in the Bus model.

Dispatches to CPU or GPU implementation based on array type parameter.

Arguments

  • outputs::NamedTuple{(:p, :q)}: Preallocated output buffers (all zeros)
  • params::NamedTuple{(:vm, :va)}: Bus voltage setpoints (unused - for consistency)
  • vars::NamedTuple{(:theta, :v)}: Current state (unused - for consistency)
  • ide::AbstractVector{Int8}: Bus type (unused - for consistency)
  • ::Type{AT}: Array type for dispatch (Vector for CPU, CuArray for GPU)

PowerfulPF.branch_residual_kernel! — Method
branch_residual_kernel!(outputs, params, vars, active, ::Type{AT})

Pure computation kernel for branch (transmission line) power flow residuals.

Implements the PI equivalent circuit model for AC transmission lines:

  • Series impedance: z = r + jx
  • Shunt charging: b (split equally at both ends for PI model)
  • Shunt conductance: g (usually zero)

Power flow equations at each end (i → j):

  • Pi = giv_i² + gvi² - viv_j(gcos(θ_ij) + bsin(θ_ij))
  • Qi = -biv_i² - bvi² - viv_j(gsin(θ_ij) - bcos(θ_ij))
  • Pj = gjv_j² + gvj² - viv_j(gcos(θ_ji) + bsin(θ_ji))
  • Qj = -bjv_j² - bvj² - viv_j(gsin(θ_ji) - bcos(θ_ji))

Where θij = θi - θ_j, and g + jb = 1/(r + jx) (series admittance).

Arguments

  • outputs::NamedTuple{(:p_i, :p_j, :q_i, :q_j)}: Power flow residuals
  • params::NamedTuple{(:r, :x, :b, :gi, :bi, :gj, :bj)}: Branch parameters
  • vars::NamedTuple{(:theta_i, :theta_j, :v_i, :v_j)}: Bus voltages
  • active::AbstractVector{Bool}: Branch in-service status
  • ::Type{AT}: Array type for dispatch (Vector for CPU, CuVector for GPU)

PowerfulPF.calc_branch_currents — Method
calc_branch_currents(v_r_i, v_i_i, v_r_j, v_i_j, r, x, b_charging, gi, bi, gj, bj) -> NamedTuple

Calculate branch current injections using PI equivalent circuit model with rectangular voltages.

Pure physics function - works on CPU and GPU (device-compatible). Called by current injection residual kernels and reports.

Arguments

  • v_r_i, v_i_i: Real and imaginary voltage at "from" bus (bus i) [pu]
  • v_r_j, v_i_j: Real and imaginary voltage at "to" bus (bus j) [pu]
  • r, x: Series resistance and reactance [pu]
  • b_charging: Total line charging susceptance [pu]
  • gi, bi: Shunt conductance and susceptance at bus i [pu]
  • gj, bj: Shunt conductance and susceptance at bus j [pu]

Returns

NamedTuple with:

  • i_r_i, i_i_i: Real and imaginary current injection at bus i [pu]
  • i_r_j, i_i_j: Real and imaginary current injection at bus j [pu]

Physics

PI model with admittance matrix Y:

I = Y * V
where V = [V_i; V_j], I = [I_i; I_j]

Y = [[Y_ii, Y_ij],
     [Y_ji, Y_jj]]

Y_series = 1/(r + jx) = g_series + j*b_series
Y_ii = Y_series + Y_shunt_i
Y_ij = -Y_series
Y_ji = -Y_series
Y_jj = Y_series + Y_shunt_j

Current injection Ii = Yii * Vi + Yij * V_j (positive = flowing into bus from branch)

Note

Sign convention: Current injection is positive flowing INTO the bus. This matches the network convention where I = Y*V naturally.

PowerfulPF.calc_branch_power_flows — Method
calc_branch_power_flows(v_i, theta_i, v_j, theta_j, r, x, b, gi, bi, gj, bj) -> NamedTuple

Calculate branch power flows using PI equivalent circuit model.

Pure physics function - works on CPU and GPU (device-compatible). Called by residual kernels and report generation.

Arguments

  • v_i, theta_i: Voltage magnitude and angle at "from" bus (bus i)
  • v_j, theta_j: Voltage magnitude and angle at "to" bus (bus j)
  • r, x: Series resistance and reactance (pu)
  • b: Total line charging susceptance (pu)
  • gi, bi: Shunt conductance and susceptance at bus i
  • gj, bj: Shunt conductance and susceptance at bus j

Returns

NamedTuple with:

  • p_i: Active power flow from bus i (pu, positive = flowing out)
  • q_i: Reactive power flow from bus i (pu)
  • p_j: Active power flow from bus j (pu)
  • q_j: Reactive power flow from bus j (pu)

Physics

PI model equations:

  • Series admittance: y = 1/(r + jx) = g + jb
  • Shunt admittance split between ends: b/2 at each end
  • Power flow: P + jQ = V·conj(I) where I = y·(Vi - Vj) + y_shunt·V

PowerfulPF.calc_transformer_power_flows — Method
calc_transformer_power_flows(v_i, theta_i, v_j, theta_j, r, x, g_mag, b_mag,
                              windv1, windv2, ang1) -> NamedTuple

Calculate transformer power flow using ANDES formulation with split π-model.

Transformer Model

  • Series admittance: y_series = 1/(r + jx) = (r - jx)/(r² + x²)
  • Magnetizing admittance: ymag = gmag + j*b_mag, a shunt at the winding 1 bus (bus i) on the bus side of the ideal transformer, so it is not scaled by the tap (RAW model)
  • Tap ratio: tap = windv1/windv2 (applied to winding 1 side)
  • Phase shift: φ = ang1 (degrees → radians, applied to winding 1)

Arguments

  • v_i, theta_i: Voltage magnitude and angle at bus i (winding 1)
  • v_j, theta_j: Voltage magnitude and angle at bus j (winding 2)
  • r, x: Series resistance and reactance (pu on system base)
  • g_mag, b_mag: Magnetizing conductance and susceptance (pu on system base)
  • windv1, windv2: Winding voltage ratios
  • ang1: Phase shift angle at winding 1 (degrees)

Returns

Named tuple (p_i=..., q_i=..., p_j=..., q_j=...) with power flows in pu.

  • Positive values: power flowing OUT of the bus (ANDES convention)

Note

This is a pure physics function compatible with CPU, GPU, and reporting. The magnetizing admittance gh/bh is a shunt at bus i only (see the model description above).

CPU kernel for PowerInjection formulation using current-based calculation.

PowerfulPF.calc_zip_load — Method
calc_zip_load(v, pl, ql, ip, iq, yp, yq, vmin) -> (p=..., q=...)

Calculate ZIP load model power consumption.

ZIP Load Model

  • P = pl·f(v) + ipv + ypv² (constant power + current + impedance)
  • Q = ql·f(v) + iqv + yqv²

where f = constant_power_factor(v, vmin) is 1 at or above the constant-power breakpoint vmin and falls off smoothly to zero below it.

Arguments

  • v: Voltage magnitude (pu)
  • pl, ql: Constant power components (MW, MVAR)
  • ip, iq: Constant current components (MW@1pu, MVAR@1pu)
  • yp, yq: Constant impedance components (MW@1pu, MVAR@1pu)
  • vmin: Constant-power breakpoint (pu), sys.settings.constant_power_vmin

Returns

Named tuple (p=..., q=...) with power consumption in pu.

Note

This is a pure physics function compatible with CPU, GPU, and reporting.

PowerfulPF.constant_power_factor — Method
constant_power_factor(v, vmin) -> f

Fraction of the constant-power load (pl, ql) drawn at voltage magnitude v (pu). At or above the breakpoint vmin (the system's constant_power_vmin) the load is constant power, f = 1; below it the load falls off as a raised cosine,

f(v) = (1 - cos(π v / vmin)) / 2,

so that f(0) = 0, f(vmin) = 1 and f'(vmin) = 0: the load and its voltage derivative are continuous at the breakpoint and the load current stays finite as v → 0. This is the low-voltage characteristic documented for PowerWorld's minimum per-unit voltage for constant power loads (cosine fall-off to zero at zero voltage, continuous derivative, default 0.7 pu); PSS/E applies a smooth characteristic below PQBRAK (default 0.7 pu). Evaluated as the equal sin(π v / (2 vmin))², which has no cancellation at small v. Branchless (ifelse) for SIMD and GPU kernels.

PowerfulPF.pq_residual_kernel! — Method
pq_residual_kernel!(outputs, params, vars, active, ::Type{AT})

Pure computation kernel for PQ load residuals using ZIP load model.

This is a pure math kernel with no addressing logic, optimized for:

  • CPU vectorization (@simd)
  • GPU execution (no branching in hot loop)
  • Easy testing and verification

Dispatches to CPU or GPU implementation based on array type parameter.

ZIP Load Model

  • P_load = pl·f(v) + ipv + ypv²
  • Q_load = ql·f(v) + iqv + yqv²

with f = constant_power_factor(v, params.vmin) (constant power above the breakpoint).

Masking

  • Inactive loads (status==false): contribute 0
  • Bus type filtering handled by scatter SharedRes mode (:add vs :set)

Arguments

  • outputs::NamedTuple{(:p, :q)}: Preallocated output buffers
  • params::NamedTuple{(:pl, :ql, :ip, :iq, :yp, :yq, :vmin)}: Load parameters and the system's constant-power breakpoint (scalar)
  • vars::NamedTuple{(:v,)}: Voltage magnitude from workspace
  • active::AbstractVector{Bool}: Mask for in-service loads
  • ::Type{AT}: Array type for dispatch (Vector for CPU, CuVector for GPU)

Performance Notes

  • Branchless computation using mask multiplication
  • @simd friendly (no conditionals in loop)
  • Zero allocation
  • Automatic CPU/GPU dispatch

Example

# CPU dispatch
pq_residual_kernel!(
    (p = p_res, q = q_res),
    (pl = pq.pl, ql = pq.ql, ip = pq.ip, iq = pq.iq, yp = pq.yp, yq = pq.yq, vmin = 0.7),
    (v = voltage_vector,),
    active_mask,
    Vector{Float64}
)

# GPU dispatch (automatically uses CUDA kernel)
pq_residual_kernel!(
    (p = p_res_gpu, q = q_res_gpu),
    (pl = pq.pl, ql = pq.ql, ip = pq.ip, iq = pq.iq, yp = pq.yp, yq = pq.yq, vmin = 0.7),
    (v = voltage_vector_gpu,),
    active_mask_gpu,
    CuVector{Float64}

PowerfulPF.calc_shunt_power — Method
calc_shunt_power(v, gl, bl) -> (p=..., q=...)

Power of a fixed shunt at voltage magnitude v, from its admittance gl + j*bl.

Returns

Named tuple (p=..., q=...) in pu:

  • p = gl*v²: active power the conductance consumes (typically gl = 0)
  • q = bl*v²: reactive power the shunt supplies to the bus; positive for a capacitor (bl > 0), negative for a reactor (bl < 0)

The residual kernels turn these into injections into the bus (positive = injection): P injection -p, Q injection q.

Arguments

  • v: Voltage magnitude (pu)
  • gl: Active conductance (pu)
  • bl: Reactive susceptance (pu); positive = capacitor, negative = reactor

Example

Capacitor bank: bl=+0.84 pu at v=1.0 → q=+0.84 (supplies reactive power)
