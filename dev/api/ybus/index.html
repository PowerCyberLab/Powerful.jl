Y-Bus Time-Domain Simulation (PowerfulYbus)

Time-domain simulation with the network represented by its sparse admittance matrix. PowerfulYbus is a standalone package: load it with using PowerfulYbus. The network solution, machine sources and system buffers are on Y-Bus Network Solution, the model traits on Y-Bus Model Interface.

Module

PowerfulYbus.PowerfulYbus — Module

PowerfulYbus - Y-Bus Network Formulation for Transient Stability

This package provides a sparse admittance-matrix (Y-bus) network formulation for transient stability simulation: the network is the sparse admittance matrix of each pre-computed topology, with the generators represented as Norton-equivalent current sources behind their internal voltage.

Key Features

  • Full sparse Y matrix per network topology, pre-computed so a fault or line trip is a cheap switch to an already-factored matrix rather than a new factorization
  • Generator admittances 1/(ra + j*xd') and constant-impedance loads in Y; constant-power and constant-current loads and current sources as injections
  • Network solve at every bus by sparse Newton iteration; one linear solve when all loads are constant impedance
  • Solvers: a fixed-step partitioned trapezoidal integrator, and OrdinaryDiffEq.jl with the network equations in the DAE (SimultaneousNetwork, sparse Jacobian) or solved in every evaluation (EliminatedNetwork, dense Jacobian)

Usage

using PowerfulYbus

# Create Y-bus TDS problem from standard TDS problem
prob_ybus = YBusTDSProblem(tds_prob; events=events)
sol = solve(prob_ybus)                    # DiffEq.jl, SimultaneousNetwork()
sol = solve_trapezoidal(prob_ybus; dt=0.001)

See Also

  • PowerfulTDS for standard residual-based TDS

Problem and Solvers

PowerfulYbus.YBusTDSProblem — Type
YBusTDSProblem{T, PROB, WS, CACHE, MT, S}

A time-domain simulation problem that represents the network by its sparse admittance (Y-bus) matrix instead of solving the full power-flow-style network equations at every step. It wraps a standard TDSProblem (same models, variables and events) and replaces only how the network is solved: every bus's voltage still comes from the same network, but a topology change (a fault, a line trip) switches to a different pre-computed Y matrix instead of re-deriving the network equations on the fly.

Build one from an ordinary TDSProblem, optionally with its own events, and solve it the same way:

tds_prob = TDSProblem(init; tspan=(0.0, 5.0))
ybus_prob = YBusTDSProblem(tds_prob)

# Or with events (a fault at bus 5 cleared by tripping line 5-1)
events = [BusFault(1.0, 1.1, 5; xf = 1e-4), BranchTrip(1.1, 1, 5, "1")]
ybus_prob = YBusTDSProblem(tds_prob; events=events)

sol = solve(ybus_prob)   # the time span comes from tds_prob

A fault or switching event gives the same simulation whether it is attached to the original TDSProblem or to the YBusTDSProblem built from it.

Extended help

Every topology the simulation can reach is factored once, when the problem is built, so that a topology change during the solve is a cheap switch to an already-factored matrix rather than a new factorization.

  • base_prob::PROB: the original TDSProblem this was built from.
  • sys_ws::WS: the buffers the Y-bus residual evaluation reads and writes.
  • network_cache::CACHE: the pre-computed Y matrices and their factorizations, one per topology the events can reach.
  • event_schedule: the pre-computed timeline of topology changes.
  • M, M_inv_diag: the DAE mass matrix and its inverse diagonal.
  • algebraic: the Newton solve of the models' own algebraic rows.
  • automata, memory_sync: the running state of each model's limiter/controller mode logic, and how it is kept in sync across the differentiation types used internally.

PowerfulYbus.YBusTDSProblem — Method
YBusTDSProblem(tds_prob; events=[])

Create a Y-bus TDS problem from a standard TDS problem.

Arguments

  • tds_prob: a TDSProblem with its dynamic models already initialized; its solver settings (from setup_tds) carry over
  • events: disturbance events (default: empty), applied together with any already on tds_prob

Events are processed at construction time, and every Y-matrix topology the events can reach is pre-computed, so a topology change during the simulation is a cheap switch to an already-factored matrix rather than a new factorization.

Supported Event Types

  • BusFault(time_on, time_off, bus, id): a bus fault
  • BranchTrip, BranchClose: line switching
  • FieldModification: a change of a field of a model (a status field, for a Branch or a Fault only)
  • SetpointChange: a change of a controller's reference value; any limiter or operating-mode logic that depends on it is re-evaluated against the new value

Any other event type is refused by name before any topology is built. A fault attached to tds_prob or to the Y-bus problem built from it gives the same simulation.

Returns

YBusTDSProblem ready for simulation with the Y-bus formulation

Example

# Simple simulation without events
ybus_prob = YBusTDSProblem(tds_prob)


# With a fault event (pre-fault, fault-on and post-fault topologies, all pre-computed)
events = [BusFault(1.0, 1.1, 5; xf = 1e-4), BranchTrip(1.1, 1, 5, "1")]  # Fault at bus 5, clear with line 1-5 trip
ybus_prob = YBusTDSProblem(tds_prob; events=events)

PowerfulYbus.EliminatedNetwork — Type
EliminatedNetwork()

The network equations are solved inside every residual evaluation (solve_network!) from the generator internal voltages; the bus voltage variables (Bus v, theta) are pinned to the solved voltages V by the residuals v - |V| and theta - ∠V at the Bus q and p rows. ForwardDiff derivatives of the solved voltages come from the implicit function theorem. The Jacobian is dense in the machine states: every solved voltage depends on every internal voltage.

With nonlinear network equations (constant-power or constant-current loads, static PV generators) the network solve iterates from the previous solution until its residual is below abstol, so the residual is a function of (u, t) up to that tolerance.

Current-source models (e.g. REGCA1) are not supported: their output current is computed by the model from the bus voltage, outside the network solve.

NetworkTreatment

PowerfulYbus.SimultaneousNetwork — Type
SimultaneousNetwork()

The bus voltages V = v∠theta are DAE unknowns (the Bus v, theta variables) and the network equations are DAE residuals at the Bus p and q rows: the real and imaginary parts of the KCL mismatch Y V - I_E - I_inj(V), or at a static generator bus its constraints (see solve_network!). The Jacobian is sparse: machine blocks and the pattern of Y.

PowerfulYbus.YBusResidual — Type
YBusResidual(prob::YBusTDSProblem, treatment::NetworkTreatment; maxiters=50, abstol=1e-8)

The Y-bus TDS DAE residual du = F(u, t) (mass-matrix form M du/dt = F(u, t)) with the network treatment treatment; callable as r(du, u, p, t) (the OrdinaryDiffEq signature). u and du hold the differential states then the algebraic variables, in the address layout of prob.base_prob.

The number type of the evaluation is eltype(du). The Float64 buffers are built at construction; the buffers of a ForwardDiff Dual type are built on its first evaluation from the same initialization (setpoints included). The automata of the models are those of prob.sys_ws (the buffers of the partitioned algebraic solve, consistent_algebraics!): every buffer reads the discrete state the automaton runtime sets there. The network solve limits maxiters, abstol apply to EliminatedNetwork and to consistent_algebraics!.

Where the network does not converge in an EliminatedNetwork evaluation (a numerical failure) the evaluation returns NaN residuals, which the integrator rejects as it does a step that blows up, and records the failure (failure: the message naming the time, the iterations, the residual and the worst rows). A right-hand side has no channel to terminate an integration; solve reads the record when the integration ends without success (network_failure_retcode), warns and returns ConvergenceFailure. A later evaluation that converges clears the record: a failure at a rejected trial point is not one of the integration.

PowerfulYbus.consistent_algebraics! — Method
consistent_algebraics!(u::Vector{Float64}, r::YBusResidual, t) -> Bool

Set the algebraic variables of u consistent with its differential states and the current network topology, for the initial state and after a topology change.

Repeats the algebraic solution of the trapezoidal solver (solve_algebraic!: the Newton iteration on the bus voltages and the models' algebraic variables) until the largest algebraic residual of r is below r.abstol. Returns true when it is; where a solve does not converge or the residual is not below r.abstol after r.maxiters passes (a numerical failure) it warns (the time, the iterations, the residual and its worst rows) and returns false, the callers stopping with a failing retcode. Errors in the models or the code throw.

CommonSolve.solve — Method
solve(prob::YBusTDSProblem[, alg]; network=SimultaneousNetwork(), maxiters=50,
      network_abstol=1e-8, verbose=false, kwargs...) -> TDSSolution

Solve the Y-bus TDS problem with OrdinaryDiffEq.jl as a mass-matrix DAE (YBusResidual).

Arguments

  • prob::YBusTDSProblem: Problem with Y-bus formulation (and events)
  • alg: OrdinaryDiffEq algorithm; default by network:
    • SimultaneousNetwork(): QNDF(linsolve=KLUFactorization()) with the sparse ForwardDiff Jacobian (pattern from the model structure, coloring)
    • EliminatedNetwork(): QNDF() with OrdinaryDiffEq's dense ForwardDiff Jacobian
  • network::NetworkTreatment: SimultaneousNetwork (default) or EliminatedNetwork
  • maxiters, network_abstol: network solve limits (EliminatedNetwork evaluations and consistent_algebraics!)
  • verbose::Bool: Print setup information
  • kwargs...: Passed to OrdinaryDiffEq.solve (initializealg defaults to NoInit(): the initial state and the state after each event are made consistent by consistent_algebraics!)

Each model's own limiter or controller mode logic (e.g. the anti-windup limits of SEXS and TGOV1) starts at its initial mode, and the solver catches the instant each limit or mode is reached, as it does for a network event. Where a mode change affects an algebraic variable or a controller state with zero time constant, those are re-solved to stay consistent with it, and after any event or mode change the solver resolves every other mode change it triggers before continuing.

Returns

TDSSolution wrapping the ODESolution (retcode as a Symbol). Where the algebraic solve of the initial state or after an event or a transition does not converge (a numerical failure, reported by a warning with the time, the iterations, the residual and its worst rows), the integration stops with retcode = :ConvergenceFailure (the trajectory so far, or the initial state alone if it is the initial one).

Example

ybus_prob = YBusTDSProblem(tds_prob; events=[BusFault(0.1, 0.2, 10, "F1")])
sol = solve(ybus_prob)                              # sparse, network in the DAE
sol = solve(ybus_prob; network=EliminatedNetwork())  # dense, network solved inside

PowerfulYbus.solve_trapezoidal — Method
solve_trapezoidal(prob::YBusTDSProblem; dt=0.01, maxiters=50, abstol=1e-8)

Solve a Y-bus TDS problem with a fixed-step trapezoidal integrator: a simple, predictable alternative to the adaptive-step OrdinaryDiffEq.jl solvers, often faster for straightforward simulations.

Uses time segments with a slightly adjusted dt within each one, so that the integration lands exactly on every event time rather than overshooting it and interpolating back. The network topology switches automatically at each event time, using the pre-computed, already-factored Y matrix for the new topology.

Arguments

  • prob: YBusTDSProblem to solve
  • dt: Nominal time step (default 0.01s) - adjusted per segment to divide evenly
  • maxiters: Max Newton steps of each network solve (default 50)
  • abstol: Network solve tolerance on the max KCL current mismatch, in pu (default 1e-8)
  • verbose: Print progress info (default false)

Failure

If a solve of the network or of the algebraic rows does not converge within maxiters (a numerical failure of a valid problem, e.g. a fault the network cannot carry), the simulation stops with a warning (the time, the iterations, the residual and its worst rows) and returns the trajectory up to the last completed step with retcode = :ConvergenceFailure (SciML's ReturnCode.ConvergenceFailure). Errors in the models or the code (a block whose rows determine no variable, a missing field) throw.

Time Segment Behavior

When events are present, the time span is divided into segments at event times. Each segment has a uniform dt adjusted to divide the interval evenly:

  • If nominal dt=0.01 and segment is 0.095s, we use dt=0.095/9 ≈ 0.01056
  • This ensures we land exactly on event times without tiny final steps

Segments smaller than 0.5×nominal_dt are merged with adjacent segments. Warnings are issued if dt varies more than 10% from nominal.

Limiters and Controller Modes

Each model's own limiter or controller mode logic (e.g. the anti-windup limits of SEXS and TGOV1) starts at its initial mode. Where a limit or mode condition is reached inside a step, that step is cut short at the instant it is reached (found to within 1e-10 max(1, |t_end|) seconds), the algebraic variables are re-solved there for consistency with the new mode, and the step then continues to its original end time. The same re-solve happens after every topology switch. The output keeps the time grid of the segments (not the shortened sub-steps).

PowerfulYbus.process_ybus_events — Method
process_ybus_events(events, sys, base_full_ybus, topology_cache, config) -> YBusEventSchedule

Process all events and pre-compute required Y-matrix topologies.

Algorithm

  1. Expand BusFault events to primitive FieldModifications
  2. Sort all events by time
  3. For each unique time point:
    • Apply cumulative modifications to full Y matrix
    • Generate TopologyKey for this state
    • Store its Y matrix in the cache

Arguments

  • events::Vector{<:Disturbance}: User-provided events
  • sys::SystemModel: System model (may be modified to add Fault models)
  • base_full_ybus::FullYMatrix{T}: Pre-fault full Y matrix
  • topology_cache::TopologyCache{T}: Cache to store computed topologies
  • config::SimConfig: The problem's config (fault impedance warning, see expand_bus_faults!)

Returns

YBusEventSchedule{T} with times and topology keys for simulation.

PowerfulYbus.build_full_ybus — Method
build_full_ybus(sys::SystemModel{T}; topology_key=nothing) where T

Build the full n×n admittance matrix from system models.

Arguments

  • sys: SystemModel containing all network elements
  • topology_key: Optional key specifying which topology (for fault/line-out scenarios)

Returns

FullYMatrix{T} containing the admittance matrix and the generator buses.

Algorithm

  1. Initialize sparse Y matrix (nbus × nbus)
  2. Add Branch contributions (series + shunt)
  3. Add Transformer contributions (with tap ratio)
  4. Add the fixed shunt contributions (every AbstractShunt model: fixed_shunt_models)
  5. Add generator admittances and constant-impedance loads

Refuses a model whose Y-bus role is FixedNetworkElement that it does not stamp (check_stamped_network_elements), naming it.

Extended help

Each series branch of admittance y = 1/(r + jx) with line-charging susceptance split as shunts jb/2 at each end contributes the standard two-port stamp: Y[from,from] += y + jb/2, Y[to,to] += y + jb/2, Y[from,to] -= y, Y[to,from] -= y (a transformer's off-nominal tap scales the off-diagonal terms and its own-bus term asymmetrically). Generator and constant-impedance load admittances are added to their own bus's diagonal only.
