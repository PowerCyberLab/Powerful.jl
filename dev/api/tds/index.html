Time-Domain Simulation (PowerfulTDS)

Setup, initialization, solution and events for phasor time-domain simulation. DYR parsing is on Dynamic Models. Initialization validation, eigenvalue and frequency response analysis are on Validation and Small-Signal Analysis.

Module

PowerfulTDS.PowerfulTDS — Module

PowerfulTDS - Time Domain Simulation Models and Solvers

This package provides dynamic models (synchronous generators, exciters, governors, renewable converters and controllers) and the phasor time-domain simulation, initialization, event, eigenvalue and frequency response tools built on them.

Usage

using Powerful
using PowerfulCases

# Solve the power flow first
case = load("ieee14")
sys = SystemModel(parse_network(case.raw))
sol = solve(ACPowerFlowProblem(sys), Newton())

# Parse dynamic data, initialize and simulate
dyr_data = parse_dynamics(case.dyr, sys)
init = setup_tds(sol, dyr_data)
tds_sol = solve(TDSProblem(init; tspan=(0.0, 10.0)))

Problem Setup

PowerfulTDS.AbstractSteadyState — Type
AbstractSteadyState

The steady state a TDSProblem starts in: Equilibrium (every state at rest) or SinusoidalSteadyState (instantaneous network states oscillating at the system frequency). It sets the initial rates of change that validate_tds_initialization checks and the default integrator of solve.

source
PowerfulTDS.Equilibrium — Type
Equilibrium()

Steady state with every state at rest at the initial time (M·ẋ = f = 0, g = 0), as a phasor simulation starts from a power flow.

source
PowerfulTDS.SinusoidalSteadyState — Type
SinusoidalSteadyState(rates)

Sinusoidal steady state: the instantaneous (three-phase) network states oscillate at the system frequency. rates holds their rates of change at t = 0, the time of the phasors the initialization builds the states from (with the states in TDSInitData.network), per model and state in the layout of TDSInitData.network; states not listed are at rest. A problem that starts at another time takes the steady state there (init_tds_buffers!, init_tds_rates: each listed state x(t₁) = x₀ cos ωt₁ + (ẋ₀/ω) sin ωt₁ and its rate, ω the system's omega_base).

PowerfulTDS.TDSConfig — Type
TDSConfig

Runtime configuration for Time-Domain Simulation.

These settings control solver behavior and can be loaded from TOML configuration files.

Fields

  • convert_pq_to_zip::Bool: Convert PQ loads to ZIP model during TDS setup (default: false)
  • p_zip::NTuple{3,Float64}: Active power ZIP composition (Z%, I%, P%), must sum to 1.0 (default: (0.0, 0.0, 1.0) = constant power)
  • q_zip::NTuple{3,Float64}: Reactive power ZIP composition (Z%, I%, P%), must sum to 1.0 (default: (0.0, 0.0, 1.0) = constant power)
  • flat_start::Bool: Reinitialize algebraic variables after events from a flat start (V = 1, θ = 0) rather than the pre-fault voltages (default: true)
  • abstol::Float64: Absolute tolerance for the DAE solver (default: 1e-6)
  • reltol::Float64: Relative tolerance for the DAE solver (default: 1e-3)
  • maxiters::Int: Maximum Newton iterations of the post-event reinitialization (default: 100)
  • adjust_limits::Bool: When a limited variable (e.g. a governor valve position) initializes outside its limits, move the violated limit to the initial value and warn, so the simulation starts in steady state with the device at its limit; false throws an error listing the violations instead (default: true). See enforce_initial_limits!.
  • locate_extrema::Bool: Catch a limit or control-mode change that is reached and released again within a single solver time step, which the integrator's own sampling would otherwise step over entirely (default: true). This covers cases such as a governor valve that briefly hits its travel limit between two accepted steps, or a protection logic condition that turns on and back off within one step. Set to false to skip this check and let the solver step over such brief events unseen; doing so is cheaper (it avoids extra function evaluations to search inside each step) but risks missing short-lived limit or mode changes, which can leave the simulation in a state inconsistent with the physical device.

solve(::TDSProblem) uses these as defaults: explicit abstol/reltol keywords and an explicit initializealg take precedence.

ZIP Model

The ZIP model represents load as combination of:

  • Z (constant impedance): P ∝ V², Q ∝ V²
  • I (constant current): P ∝ V, Q ∝ V
  • P (constant power): P = const, Q = const

Example TOML

[solver.TDS]
convert_pq_to_zip = true
p_zip = [0.3, 0.3, 0.4]  # 30% Z, 30% I, 40% P for active power
q_zip = [0.2, 0.3, 0.5]  # 20% Z, 30% I, 50% P for reactive power
abstol = 1e-8

Example Julia

settings = TDSConfig(
    convert_pq_to_zip = true,
    p_zip = (0.3, 0.3, 0.4),
    q_zip = (0.2, 0.3, 0.5)
)

States and setpoints a TDSProblem starts from.

PowerfulTDS.TDSInitialization — Type
TDSInitialization

The dynamic states and controller setpoints computed from a converged power flow solution: the operating point a time-domain simulation starts from at t = 0. Build it with setup_tds, then pass it to TDSProblem.

Fields

  • dyn::NamedTuple - Per-model initial states, e.g. (GENROU=(delta=[], omega=[]), ...) (rotor angle delta in rad, speed omega in pu, one entry per instance)

init.dyn.GENROU.omega      # Initial speeds (should be ~1.0 pu)
init.setpoints.TGOV1.P_m0  # Mechanical power setpoints

PowerfulTDS.TDSProblem — Type
TDSProblem{T, FType, B}

A time-domain simulation to run: a power system with its dynamic models (generators, governors, exciters) already initialized at a steady-state operating point, a time span, and a list of disturbance events. Pass it to solve to integrate the system's dynamics.

Build one from a TDSInitialization (the result of setup_tds):

prob = TDSProblem(init; tspan=(0.0, 5.0), events=[BusFault(0.5, 0.6, 10), BranchTrip(1.0, 1, 5, "1")])
sol = solve(prob)

What You Can Read or Set

  • tspan::Tuple{T, T}: simulation time span (t_start, t_end) in seconds, set as a keyword to TDSProblem(init; tspan=...).
  • events::Vector: the disturbances to apply during the run (BusFault, BranchTrip, BranchClose, FieldModification, SetpointChange), also set as a keyword.
  • sys::SystemModel: the system being simulated, with dynamic models in place of the PV/Slack generators they replace; read this to inspect the model instances and their parameters.
  • config::SimConfig: the solver settings (TDSConfig) that solve uses as defaults; explicit solve keywords override them.

See Also

  • setup_tds: build the initialization this is constructed from
  • BranchTrip, BusFault: event constructors
  • validate_tds_initialization: check initial residuals

Example

using Powerful, PowerfulCases

case = load("ieee14")
sys = SystemModel(parse_network(case.raw))
sol_pf = solve(ACPowerFlowProblem(sys), Newton())

dyn_data = parse_dynamics(case.dyr, sys)
init = setup_tds(sol_pf, dyn_data)

events = [BusFault(0.5, 0.6, 10), BranchTrip(1.0, 1, 5, "1")]
prob = TDSProblem(init; tspan=(0.0, 5.0), events=events)

sol = solve(prob)

Extended help

  • formulation::FType: the DAE formulation, supported by every model of the system (checked by the constructor).
  • address_manager::AddressManager: maps model variables and residuals to positions in the DAE's state and residual vectors.
  • backend::B: the automatic-differentiation backend used to build the Jacobian (ForwardDiffBackend or EnzymeBackend).
  • traces::StructuralTraces: which variables each model's operating-mode logic reads, discovered on the first solve of the problem and reused by subsequent solves and by working copies.

PowerfulTDS.TDSProblem — Method
TDSProblem(init::TDSInitialization; kwargs...)

Create a TDS problem from initialization (which contains the system).

Arguments

Keyword Arguments

PowerfulTDS.apply_zip_conversion! — Method
apply_zip_conversion!(sys::SystemModel, sol_pf::AbstractSteadyStateSolution, settings::TDSConfig)

Convert the loads of sys (the models that are is_zip_load, such as PQ) to the ZIP model while preserving their consumption at the operating voltage of the power flow solution sol_pf. Refuses, before converting any load, a system holding a model that does not declare whether it is a ZIP load (check_zip_load_declared).

This implements PSS/E's "Reconstruct loads using present voltage" operation: each converted load consumes the same power at the solved voltage as before. Loads are matched to the power flow by their (bus, id) key.

Only the loads of sys change. setup_tds converts the loads of the systems it builds (copies of the power flow models), so the power flow system of sol_pf keeps its loads and a later power flow on it is unaffected.

ZIP Model

After conversion, load power consumption becomes voltage-dependent:

  • P = pl·f(v) + ipV + ypV² (constant power + current + impedance)
  • Q = ql·f(v) + iqV + yqV²

with f = constant_power_factor(v, vmin) (1 above the constant-power breakpoint).

Algorithm

For each load at operating voltage Vop, with total consumption Ptotal, Q_total:

yp_new = z% × P_total / V_op²   # Constant impedance (Z)
ip_new = i% × P_total / V_op    # Constant current (I)
pl_new = p% × P_total / f       # Constant power (P)

Arguments

  • sys::SystemModel: System whose loads are converted (in place)
  • sol_pf::AbstractSteadyStateSolution: Solved power flow (bus voltages)
  • settings::TDSConfig: Settings containing p_zip and q_zip tuples

Example

sol = solve(ACPowerFlowProblem(sys), Newton())
settings = TDSConfig(
    convert_pq_to_zip = true,
    p_zip = (0.3, 0.3, 0.4),  # 30% Z, 30% I, 40% P
    q_zip = (0.2, 0.3, 0.5)   # 20% Z, 30% I, 50% P
)
apply_zip_conversion!(sys_tds, sol, settings)

See Also

  • TDSConfig: Configuration struct with ZIP percentages
  • validate: Validates that ZIP percentages sum to 1.0
source
PowerfulTDS.setup_tds — Method
setup_tds(sol_pf, dyn_models; config=SimConfig()) -> TDSInitialization

Prepare TDS system and compute initial conditions from power flow solution.

This is the recommended entry point for TDS simulation setup. It performs:

  1. System preparation (merging dynamic models with power flow system)
  2. Model linking (mapping dynamic → static models)
  3. State initialization from power flow solution

Arguments

  • sol_pf: Power flow solution (contains system via get_system(sol_pf))
  • dyn_models: Dynamic models as NamedTuple (e.g., from parse_dynamics)

Keyword Arguments

  • config::SimConfig: Simulation configuration (default: SimConfig())

Returns

  • TDSInitialization: Complete initialization containing system, states, setpoints, and pf snapshot

Example

init = setup_tds(sol_pf, dyr_data)

sol = solve(prob)

# Access system for inspection
init.sys.models  # View dynamic models

# With custom config (system-wide settings come from the SystemModel)
config = SimConfig(solver = (TDS = TDSConfig(abstol = 1e-8),))
init = setup_tds(sol_pf, dyr_data; config = config)

PowerfulTDS.create_model_links — Method
create_model_links(sys_pf::SystemModel, dynamic_models::NamedTuple) -> ModelLinks

Build replacement links between dynamic models and power flow models.

Used for replacement filtering: determines which PV/Slack instances to remove from the merged TDS system (replaced by GENCLS, GENROU, etc.).

PowerfulTDS.prepare_tds_system — Method
prepare_tds_system(sys_pf, sol_pf, dynamic_models; config) -> Tuple{SystemModel, ModelLinks}

Create TDS-ready system with dynamic models, filtering replaced static models.

Example

# Staged API (for debugging)
sys_tds, links = prepare_tds_system(sys_pf, sol_pf, dynamic_models)
init = TDSInitialization(sys_tds, links, sol_pf)
prob = TDSProblem(init; tspan=(0.0, 10.0))

# Standard API (most users) - use setup_tds instead
init = setup_tds(sol_pf, dynamic_models)
prob = TDSProblem(init; tspan=(0.0, 10.0))

Algorithm

  1. Create links between dynamic and power flow models
  2. Build replacement masks from links
  3. derive_system: remove the replaced static instances, add the dynamic models (those per unit on the base of their linked device converted to the system base), re-index, and retrieve external params for the dynamic models
  4. Apply ZIP conversion if enabled, to the loads of the TDS system (copies: sys_pf keeps its loads)

Returns

  • sys_tds::SystemModel - TDS system with filtered static + dynamic models
  • links::ModelLinks - Mapping from dynamic to static (needed for initialization)

Design Note

This function separates system construction from initialization:

  • Construction: Parameter setup (this function)
  • Initialization: State values (initializedynamicmodels)

Solving

CommonSolve.solve — Function
solve(prob::TDSProblem, alg=_default_tds_alg(prob); initializealg, verbose=false, validate=true, recorder=nothing, kwargs...)

Solve time-domain simulation problem using data stored in prob.

Uses ODEProblem with mass matrix formulation (M * du/dt = f(u,t)) and sparse Jacobians. Default solver is QNDF with KLUFactorization for efficient sparse linear solves, and FBDF of order at most 2 for a SinusoidalSteadyState problem (see _default_tds_alg).

Arguments

  • prob::TDSProblem - TDS problem with initialization data
  • alg - Solver algorithm (default: _default_tds_alg(prob))
  • initializealg - DAE initialization algorithm for events (default: PowerFlowInit with maxiters and flat_start from the problem's TDSConfig, converging to REINIT_TOL_FRACTION of abstol):
    • PowerFlowInit() - Flat start V=1, current theta (the default)
    • PowerFlowInit(initial_guess=:pre_fault) - Pre-fault V magnitudes, current theta (unsuitable when the angles have moved far from their pre-fault values: after a long fault or a pole slip it may not converge)
    • PowerFlowInit(initial_guess=:current) - Use current voltages (converged in the long-fault cases tested, where the other two did not; may converge to wrong solution from low voltages)
    Which guess converges depends on the case. A reinitialization that does not converge terminates the integration with sol.retcode == :ConvergenceFailure, with a warning, the trajectory kept up to that instant. An inconsistent initial state throws (DiffEq's check at t0)
    • BrownFullBasicInit() - DiffEq's generic initializer (may fail for severe faults)
    • NoInit() - Skip reinitialization (not recommended)
  • verbose - Print progress information (default: false)
  • validate - Validate initialization before solving (default: true). Checks that the DAE starts in steady state (see validate_tds_initialization).
  • recorder - Optional InjectionRecorder for tracking per-model contributions to SharedRes
  • kwargs... - Passed to OrdinaryDiffEq.solve(). abstol and reltol default to the problem's TDSConfig values.

Example

# Basic solve (QNDF with KLUFactorization is default)
sol = solve(prob)

# With verbose output
sol = solve(prob; verbose=true)

# Use pre-fault voltages (good for fault-on/fault-off scenarios)
sol = solve(prob; initializealg=PowerFlowInit(initial_guess=:pre_fault))

# With injection recording (track model contributions to the bus power balance)
bus_keys = [(i,) for i in prob.sys.models.Bus.i]
monitor = InjectionMonitor(:Bus => [:p => bus_keys, :q => bus_keys])
recorder = InjectionRecorder(monitor, prob)  # Creates from TDSProblem
sol = solve(prob; recorder=recorder)
table = contributions_table(recorder, :Bus, :p, bus_keys[1])

PowerfulTDS.compute_initialization_order — Method
compute_initialization_order(sys::SystemModel) -> InitializationOrder

Compute initialization order from model metadata using topological sort.

Dependencies are inferred automatically from InitInput declarations:

  • InitInput(:from_group_init, ...) → depends on the referenced group
  • InitInput(:from_observation, ...) or InitInput(:from_solution, ...) → depends on :power_flow

Algorithm

  1. Collect all models and the groups they implement (implements_group)
  2. Build model → group lookup for dependency resolution
  3. Infer dependencies from InitInput metadata
  4. Topological sort to determine group order
  5. Validate no cycles exist (Kahn's algorithm detects cycles)

Throws

  • ErrorException if circular dependencies detected

PowerfulTDS.initialize_dynamic_models — Method
initialize_dynamic_models(
    sys::SystemModel,
    links::ModelLinks,
    pf_sol::AbstractSteadyStateSolution
) -> NamedTuple

Initialize the dynamic models of sys from the power flow solution pf_sol, in dependency order using vectorized gathering.

setup_tds calls it for the phasor system it builds. A package that builds its own system around the TDS dynamic models (with bus models of its own that implement :bus_group) calls it to initialize them. To simulate a phasor system, use:

prob = TDSProblem(setup_tds(sol_pf, dynamic_models); tspan=(0.0, 10.0))

Algorithm

  1. Compute initialization order via topological sort
  2. For each group in order:
    • For each model in group:
      • Call model's initializedynamicstates() with prior_init from previously initialized models
      • Store results for use by subsequent models
  3. Build setpoints from initialized states using model metadata
  4. Extract PF snapshot (v, theta)
  5. Return unified init NamedTuple

Returns

NamedTuple with three fields:

  • dyn: Per-model initialized states (GENCLS=(delta, omega, ...), ...)
  • setpoints: Per-model setpoints for holding equations (GENCLS=(Pm0, Eq0), ...)
  • pf: Power flow snapshot (v=[], theta=[])

PowerfulTDS.resolve_init_inputs — Method
resolve_init_inputs(ctx::InitContext, model_name::Symbol, metadata::ModelMetadata) -> NamedTuple

Resolve all initialization inputs declared in model metadata.

Each input's kind field determines the resolution strategy:

  • :from_solution: Fetch from DAE solution vector (V, θ)
  • :from_observation: Compute from linked power flow model (P, Q)
  • :from_group_init: Get from previously initialized model in group

Arguments

  • ctx::InitContext: Initialization context with pf_sol, sys, links, and accumulated states
  • model_name::Symbol: Name of the model being initialized (e.g., :GENCLS)
  • metadata::ModelMetadata: Model metadata with init_inputs declarations

Returns

NamedTuple with one field per InitInput entry, each containing a vector of values, and one per derived parameter of the model (RatingRatio, as the ratio of its rating to the system base).

Example

PowerfulTDS.PowerFlowInit — Type
PowerFlowInit <: DAEInitializationAlgorithm

Re-solve the network after an event (a fault, a breaker trip, a setpoint change) while holding the dynamic states (rotor angle, speed, flux, controller integrators — any state with a time constant) fixed at their value just before the event. This is the standard way to bring a dynamic simulation back to a consistent operating point after a discrete change in the network or in a limiter's mode, without perturbing the machine and controller states that evolved smoothly through it.

Internally this solves the power-flow-like algebraic equations (and any state whose time constant is zero, which the solver treats like an algebraic variable) with Newton iteration, which is more robust for power system network equations than generic DAE initializers.

Initial Guess Options

Pass initial_guess to control the starting point of the Newton iteration:

  • :flat_start (the default) — start from V = 1 pu, current bus angles. Converges in most short-fault cases.
  • :pre_fault — start from the voltage magnitudes just before the event, current bus angles. Good for temporary, short faults; a poor guess once the angles have swung far from their pre-event values (a long fault or a pole slip), since the pre-event magnitudes no longer match the post-event angles.
  • :current — start from whatever voltages the integrator currently holds. Tends to converge after long or severe faults where the other two guesses fail, but a Newton iteration started from depressed voltages can also converge to a spurious low-voltage solution.

No single guess is the most robust for every case; if a reinitialization fails to converge with the default, retry with one of the others. (Example: ieee14 with GENROU, a 2 s fault at bus 3, xf = 0.003: :flat_start and :pre_fault fail to converge at clearing, and :current succeeds. Short faults at buses 4 and 10, 0.1 s, converge with every guess.)

This initial guess applies only to reinitialization after a network event. When a limiter or controller changes mode on its own (for example a governor valve reaching its travel limit), the solver instead resumes from the state the integrator already holds, since that state was already consistent just before the mode change.

Reinitialization Failure

A reinitialization that does not converge within maxiters, or whose result does not satisfy the DAE at that instant, is treated as a numerical failure of the simulation (not a code error): it warns with the time, iteration count, residual and worst-offending rows, and the simulation stops with sol.retcode == :ConvergenceFailure, keeping the trajectory up to that point. An inconsistent initial state at the start of a simulation (t0) still throws, since that indicates a model or setup error rather than a physical outcome.

Usage

sol = solve(prob, FBDF(); initializealg=PowerFlowInit())                       # flat start (default)
sol = solve(prob, FBDF(); initializealg=PowerFlowInit(initial_guess=:pre_fault))
sol = solve(prob, FBDF(); initializealg=PowerFlowInit(initial_guess=:current))

Extended help

  • abstol: convergence tolerance on the current mismatch; nothing (the default) ties it to the simulation's own absolute tolerance once bound to a solve, 1/100th of it.
  • maxiters: maximum Newton iterations (default: 100).
  • adapter, pre_fault_v: bound automatically by solve(); not set by users.

PowerfulTDS.reinitialize_algebraic! — Method
reinitialize_algebraic!(u::AbstractVector, adapter::TDSAdapter, t; kwargs...)

Reinitialize the variables without mass of u, the state at time t, after a topology change (fault, trip, etc) or a transition of an automaton: the algebraic variables y, and the differential states whose mass is zero (a zero inertia, a bus without capacitance), which the DAE M u̇ = F(u) constrains as algebraic.

Solves the rows without mass of the DAE (g(x, y) = 0, and the rows of the states without mass, as the integration evaluates them: a row the reduction of state-only constraints replaces by its derivative in that form) for those variables, with the states with mass fixed, using Modified Newton:

z_{k+1} = z_k - J^{-1} * r(z_k)

where the Jacobian J = ∂r/∂z is only recomputed every jac_update_freq iterations. Without states without mass, z = y and r = g. The bus power balance rows are solved as current mismatch (divided by the bus voltage magnitude, see BusPowerRows), so abstol bounds the current mismatch of those rows.

Arguments

  • u: Combined state vector [x; y] - modified in place
  • adapter: TDSAdapter with residual evaluation capability
  • t: The time of the state u (no default: a model's residuals can depend on it directly, so a solve at another time solves other equations)
  • maxiters: Maximum Newton iterations (default: 100)
  • abstol: Convergence tolerance on ||r|| (default: 1.0e-8)
  • jac_update_freq: Jacobian update frequency (default: 5)
    • 1 = standard Newton (Jacobian every iteration)
    • >1 = Modified Newton (reuse Jacobian for multiple iterations)
  • verbose: Print per-iteration progress (default: false)

Returns

true if converged, false otherwise

Performance

Uses Modified Newton by default: the Jacobian is only recomputed every jac_update_freq iterations, significantly reducing computation time for large systems. The KLU factorization is also reused when the Jacobian hasn't changed.

For a 70k-bus system with ~117ms per Jacobian computation, this can reduce reinitialization time from ~2.5s (14 iterations × 160ms) to ~1s (3 Jacobian updates + 11 cheap iterations).

Cached infrastructure: The closure, Jacobian prep, matrix, and backend are cached in TDSAdapter after the first call, saving ~50-200ms per subsequent event.

PowerfulTDS.enforce_initial_limits! — Method
enforce_initial_limits!(sys, dyn, adjust::Bool) -> Vector{NamedTuple}

PowerfulTDS.TDSAdapter — Type
TDSAdapter

Adapter bridging DiffEq.jl's combined state vector with internal buffers.

Mass Matrix DAE Formulation

The TDS system is a DAE in mass matrix form:

M * du/dt = [f(x,y); g(x,y)]

where:

  • u = [x; y] - combined state vector (differential x, algebraic y)
  • M = diag(M_x, 0) - singular mass matrix (zeros for algebraic equations)
  • f(x,y) - differential residuals (dx/dt = f)
  • g(x,y) = 0 - algebraic constraints (network equations)

Example

adapter = TDSAdapter(adcache, prob_tds)
ode_fn! = (du, u, p, t) -> evaluate!(du, adapter, u, t, ODEInterface())
ode_func = ODEFunction(ode_fn!; mass_matrix=adapter.mass_matrix)
sol = solve(ODEProblem(ode_func, u0, tspan), QNDF(linsolve=KLUFactorization()))

PowerfulTDS.enforce_state_constraints! — Method
enforce_state_constraints!(u, adapter, t; atol=1e-10) -> Bool

Restore the state-only constraints of the adapter's reduction at u, the state at time t, after an event that made states jump, such as a fault current reset when a fault clears at a bus whose every connection is an inductor, or a mode that holds a constraint is entered (the constraints of the modes the automata are in, gate_open). Returns whether u changed.

The reduced rows keep A(t)·x + b at its value, so a jump that leaves A(t)·x + b = c ≠ 0 would persist (A(t) the constraint coefficients at t, constraint_matrix; c the value of the constraint read from the residual, _constraint_value). The correction is the one that conserves the flux of every inductor loop: the change Δx minimizes Δxᵀ M Δx subject to A(x + Δx) = 0, i.e. Δx = -M⁻¹Aᵀ (A M⁻¹ Aᵀ)⁻¹ c with A = A(t), over the states of in-service instances (the states of out-of-service instances, e.g. a cleared fault's reset currents, keep their values). This is project_states! with the MinimumNorm policy and the inverse masses as weights, which moves every state of a constraint; a mode that governs a state uses the AlongStates policy (governed_states.jl).
