Core: Islands and Outages (PowerfulCore)

Splitting a system into islands, and the contingency and outage types used by contingency analysis and time-domain events. These names are defined in PowerfulCore.System and exported by PowerfulCore.

Multi-Island Systems

PowerfulCore.System.split_islands — Method
split_islands(sys::SystemModel; auto_analyze::Bool=true) -> Union{SystemModel, Vector{SystemModel}}

Extract disconnected islands as separate SystemModel instances.

Returns the original system if connected, or a vector of independent island systems. Each island has its own AddressManager and IndexOrder, and can be solved independently.

Note: ACPowerFlowProblem calls this automatically during construction. For most use cases, simply call solve(ACPowerFlowProblem(sys), Newton()) which handles islands transparently.

Arguments

  • sys::SystemModel: Original system
  • auto_analyze::Bool=true: Run topology analysis if not cached

Returns

  • SystemModel: If single island (returns original, zero overhead)
  • Vector{SystemModel}: If multiple disconnected islands

Example

sys = SystemModel(case)
result = split_islands(sys)

if result isa Vector
    println("System has $(length(result)) islands")
    for island in result
        sol = solve(ACPowerFlowProblem(island), Newton())
    end
else
    sol = solve(ACPowerFlowProblem(result), Newton())
end

See Also

  • analyze_topology: Analyze connectivity without splitting
  • ACPowerFlowProblem: Auto-handles islands during construction

PowerfulCore.System.Contingency — Type
Contingency(name, actions)

A named contingency consisting of one or more outage actions.

Example

Contingency("LINE_1_2", [BranchOutage(1, 2, "1")])            # N-1 branch
Contingency("GEN_101", [GeneratorOutage(101, "1")])          # N-1 generator
Contingency("XFMR_1_2", [Transformer2WOutage(1, 2, "1")])     # N-1 transformer
Contingency("N2_TEST", [BranchOutage(1, 2, "1"), GeneratorOutage(101, "1")])

PowerfulCore.System.apply_contingency! — Method
apply_contingency!(status, sys, cont::Contingency, topo, bus_device_map)
    -> Dict{Symbol, Vector{Int}}

Take the instances removed by the actions of cont out of service in status (a status dict of the base case, e.g. from copy_status_dict), then de-energize the islands this leaves without a slack bus (see deenergize_islands!). Returns the instances switched off, keyed by model (:Bus for de-energized buses). The system itself is not modified.

topo is analyze_topology(sys; build_incidence=true) and bus_device_map is build_reverse_terminal_map(sys, :Bus), both of the base case. The islands are only searched when the network can split: when a bridge is removed, or two or more branches or transformers.

source
PowerfulCore.System.deenergize_islands! — Method
deenergize_islands!(switched, status, topo, bus_device_map) -> switched

Take out of service, in status, every bus that the in-service branches and transformers no longer connect to a slack bus, and every device on such a bus; these islands have no reference and cannot be solved. The instances switched off are appended to switched (keyed by model, :Bus for the buses).
