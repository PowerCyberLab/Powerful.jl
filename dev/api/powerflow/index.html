Power Flow (PowerfulPF)

AC and DC power flow problems, algorithms and solutions. Result access and reports are on Power Flow Results and Reports.

Module

PowerfulPF.PowerfulPF — Module

PowerfulPF - Power Flow Models and Solvers

This package provides network models (Bus, PQ, PV, Branch, etc.) and power flow solvers (Newton-Raphson, Fast Decoupled) for steady-state power system analysis.

Usage

using PowerfulCore, PowerfulPF
using PowerfulCases

# Load and solve (parse_network and SystemModel come from PowerfulCore)
case = parse_network(load("ieee14").raw)
sys = SystemModel(case)
prob = ACPowerFlowProblem(sys)
sol = solve(prob, Newton())  # or RobustNR()

PowerfulPF.ACPowerFlowProblem — Type
ACPowerFlowProblem <: PowerFlowProblem

AC power flow problem with full nonlinear equations.

Solves the nonlinear system g(y) = 0 where:

  • y contains bus voltage magnitudes and angles
  • g contains power balance equations at each bus

Automatically detects and handles multi-island systems when auto_split=true (default).

Fields

  • sys::Union{SystemModel, Vector{SystemModel}}: Power system (single or multi-island)
  • initial_guess::Union{Nothing, Vector{Float64}}: Starting point for iteration

Constructors

# Use system's current state as initial guess (default)
# Automatically detects islands
prob = ACPowerFlowProblem(sys)

# Provide custom initial guess (single-island systems only)
prob = ACPowerFlowProblem(sys; initial_guess=y0)

# Disable auto-split for manual island handling
prob = ACPowerFlowProblem(sys; auto_split=false)

Example

using PowerfulCore, PowerfulPF, PowerfulCases

# Load and set up system
case = load("ieee14")
sys = SystemModel(parse_network(case.raw))

# Create problem (auto-detects islands)
prob = ACPowerFlowProblem(sys)

# Solve with default algorithm
sol = solve(prob)  # Works for single or multi-island!

# Or specify algorithm
sol = solve(prob, Newton(abstol=1e-10))

PowerfulPF.CUDSSSolver — Type
CUDSSSolver <: LinearSolver

GPU sparse direct solver via CUDSS (CUDA Direct Sparse Solver).

Requires a CUDA-capable GPU and a GPU package that provides gpu_linear_solver. Works in hybrid mode: CPU computes Jacobian, GPU performs factorization and triangular solves.

Usage

prob = ACPowerFlowProblem(sys)
sol = solve(prob, Newton(linear_solver=CUDSSSolver()))

Performance

Best for large systems (>10k buses) where GPU factorization speedup outweighs PCIe transfer overhead. Data transfers happen automatically each Newton iteration.

PowerfulPF.DishonestNewton — Type
DishonestNewton(; update_freq=3, maxiters=50, abstol=1e-8) <: ACMethod

Dishonest (modified) Newton method: the Jacobian is refreshed and refactorized only every update_freq iterations, reusing the factorization in between. Trades convergence speed for reduced factorization cost; useful for very large systems where Jacobian factorization dominates. Uses KLU on CPU, single-island systems.

source
PowerfulPF.FastDecoupled — Type
FastDecoupled <: ACMethod

Fast Decoupled Power Flow method with constant Jacobian matrices.

Exploits the weak coupling between P-θ and Q-V in power systems to use constant B' and B" matrices, factored once and reused across all iterations.

Variants

  • :XB - Traditional fast decoupled (neglects R, uses X only)
  • :BX - Alternate formulation (includes R effects)

Performance

2-3x faster than Newton-Raphson for well-conditioned transmission networks. Typical convergence: 10-20 iterations vs 3-5 for Newton (but smaller subsystems).

When to Use

✓ Large transmission networks (>1000 buses) ✓ Well-conditioned systems (high X/R ratio) ✓ Repeated solves (factorizations reused) ✗ Stressed systems near voltage collapse ✗ Distribution networks (low X/R ratio)

PowerfulPF.KLUSolver — Type
KLUSolver <: LinearSolver

Sparse LU factorization via KLU.jl with fill-reducing ordering.

KLU is optimized for circuit simulation and works excellently for power system Jacobians.

CommonSolve.solve — Function
solve(prob::PowerFlowProblem, alg=default_algorithm(prob); kwargs...)

Solve a power flow problem with the specified algorithm.

This is the main entry point for the modern API. Matches the interface used by DifferentialEquations.jl, NonlinearSolve.jl, and Optimization.jl.

Arguments

  • prob::PowerFlowProblem: Problem to solve (e.g., ACPowerFlowProblem)
  • alg: Algorithm to use (defaults to problem-specific default)
  • kwargs...: Additional solver-specific options

Returns

Solution object with fields:

  • converged::Bool: Whether solver converged
  • iterations::Int: Number of iterations taken
  • residual_norm::Float64: Final residual norm
  • Additional fields depending on solver

Example

using PowerfulCore, PowerfulPF, PowerfulCases

# Load system
case = load("ieee14")
sys = SystemModel(parse_network(case.raw))

# Create problem
prob = ACPowerFlowProblem(sys)

# Solve with default algorithm
sol = solve(prob)

# Solve with specific algorithm
sol = solve(prob, Newton(abstol=1e-10))

# Solve with robust method
sol = solve(prob, RobustNR())

# Check convergence
if sol.converged
    println("Converged in ", sol.iterations, " iterations")
    println("Final residual: ", sol.residual_norm)
else
    @warn "Did not converge"
end

See also: ACPowerFlowProblem, Newton, RobustNR

PowerfulPF.FastDecoupledXB — Method
FastDecoupledXB(; kwargs...) -> AlgorithmConfig

Fast Decoupled Power Flow with XB formulation (neglects resistance).

XB variant uses susceptance-only approximation: B'[i,j] = -bij = -Im(Yij). Best for transmission networks with high X/R ratio.

Keyword Arguments

  • maxiters::Int=100: Maximum iterations (FDPF typically needs 2-4x more than Newton)
  • abstol::Float64=1e-6: Convergence tolerance on max(|ΔP|, |ΔQ|)
  • ordering::Symbol=:AMD: KLU fill-reducing ordering (:AMD, :COLAMD, :natural)

Example

prob = ACPowerFlowProblem(sys, PowerInjection())
sol = solve(prob, FastDecoupledXB())  # 2-3x faster than Newton for large systems

# Tighter tolerance
sol = solve(prob, FastDecoupledXB(abstol=1e-8, maxiters=50))

PowerfulPF.Newton — Method
Newton(; kwargs...) -> AlgorithmConfig

Fast native Newton-Raphson with KLU sparse solver (recommended default).

Keyword Arguments

  • maxiters::Int=50: Maximum iterations
  • abstol::Float64=1e-8: Convergence tolerance on ||g||∞
  • reltol::Float64=1e-8: Relative tolerance (ignored by the native solver, which checks abstol)
  • ordering::Symbol=:AMD: KLU fill-reducing ordering (:AMD, :COLAMD, :natural)
  • linear_solver::Union{Nothing, LinearSolver}=nothing: Override linear solver (e.g., CUDSSSolver())

Algorithm Stack

  • Method: Newton-Raphson (full Jacobian, quadratic convergence)
  • Globalization: None (pure Newton steps)
  • Backend: Native (PowerfulPF's optimized implementation)
  • Linear solver: KLU with AMD ordering (default), or user-specified

Example

prob = ACPowerFlowProblem(sys)

# Use defaults (abstol=1e-8, maxiters=50, AMD ordering)
sol = solve(prob, Newton())

# Tighter tolerance for sensitivity analysis
sol = solve(prob, Newton(abstol=1e-12))

# More iterations for difficult cases
sol = solve(prob, Newton(maxiters=100))

# Try different ordering
sol = solve(prob, Newton(ordering=:COLAMD))

# Use GPU linear solver (requires CUDA + CUDSS)
sol = solve(prob, Newton(linear_solver=CUDSSSolver()))

PowerfulPF.RobustNR — Method
RobustNR(; kwargs...) -> AlgorithmConfig

Robust Newton via NonlinearSolve.jl with automatic algorithm selection.

Uses NonlinearSolve.jl's default algorithm which automatically selects trust region, Levenberg-Marquardt, or other robust methods based on problem characteristics.

Keyword Arguments

  • maxiters::Int=50: Maximum iterations
  • abstol::Float64=1e-8: Convergence tolerance
  • reltol::Float64=1e-8: Relative tolerance, passed to NonlinearSolve

Algorithm Stack

  • Method: Newton-Raphson (interface to NonlinearSolve)
  • Globalization: Automatic (trust region, line search, etc.)
  • Backend: NonlinearSolve.jl
  • Linear solver: Automatic (typically KLU)

When to Use

  • Native Newton fails to converge
  • Poor initial guess (e.g., high-load stressed systems)
  • Research/comparison purposes
  • Exploring NonlinearSolve.jl's features

Example

prob = ACPowerFlowProblem(sys)

# Robust solver (slower but more reliable)
sol = solve(prob, RobustNR())

# Compare with native Newton
sol_native = solve(prob, Newton())
sol_robust = solve(prob, RobustNR())

Newton-Raphson

PowerfulPF.NewtonWorkspace — Type
NewtonWorkspace{SYS, JT, BT, PT}

Pre-allocated workspace for Newton-Raphson power flow solver.

Separates one-time setup (sparsity detection, coloring, allocation) from allocation-free Newton iterations. Uses plain vectors for iteration state, eliminating aliasing issues and ensuring zero allocations in the hot loop.

Type Parameters

  • SYS: SystemModel type (matches CachedAutodiffWorkspace)
  • JT: Jacobian type (SparseMatrixCSC)
  • BT: Backend type for differentiation (AutoSparse)
  • PT: Prep type for Jacobian (PreparedJacobian)

Fields

  • cache::CachedAutodiffWorkspace{SYS}: Residual evaluator
  • iter_dae::DAE{Vector{Float64}}: Current iteration state (y, g)
  • ls_dae::DAE{Vector{Float64}}: Line search trial state (yls, gls)
  • dy::Vector{Float64}: Newton update direction (RHS buffer)
  • J::SparseMatrixCSC: Sparse Jacobian matrix
  • jac_prep: Prepared Jacobian (coloring, etc.)
  • jac_backend: Differentiation backend
  • linear_solver: Factorization cache (KLULinearSolver, or the GPU solver of gpu_linear_solver)

Example

# One-time setup (expensive: sparsity, coloring, allocation)
prob = ACPowerFlowProblem(sys)
workspace = setup_powerflow_newton(prob; verbose=true)

# Solve multiple times with different initial conditions (allocation-free!)
y0_1 = copy(workspace.iter_dae.y)
sol1 = solve_powerflow_newton!(workspace, y0_1; abstol=1e-8)

y0_2 = y0_1 .* 1.1  # Different initial guess
sol2 = solve_powerflow_newton!(workspace, y0_2; abstol=1e-10)

# Benchmark iterations only (no setup overhead)
@btime solve_powerflow_newton!($workspace, $y0_1; abstol=1e-8, verbose=false)

Design Notes

Power flow solves algebraic equations only. When state variables (x, f) are added for dynamic simulation, they will be added as explicit fields to this workspace or a separate DynamicSimWorkspace will be created.

source
PowerfulPF.ResidualFunctor — Type
ResidualFunctor

Functor wrapping ADCache and status for consistent types with Enzyme.

Anonymous closures like (g, y) -> adcache(g, y, status, 0.0) get different compiler-generated types each time they're created. This breaks Enzyme's BatchDuplicated which requires homogeneous types.

This struct provides a stable type that can be reused between prepare_jacobian and jacobian! calls.

It evaluates at t = 0: a power flow's state is the operating point a simulation starts from, at the start of the time axis, and its residuals do not depend on time.

PowerfulPF.setup_powerflow_newton — Method
setup_powerflow_newton(prob::ACPowerFlowProblem; kwargs...) -> NewtonWorkspace

Perform all one-time setup for Newton-Raphson power flow solver.

This function separates setup cost from iteration cost, enabling:

  • Precise benchmarking of iterations only
  • Reusing workspace for multiple solves with different initial conditions
  • Clear visibility into setup vs iteration allocation

Arguments

  • prob::ACPowerFlowProblem: Power flow problem with system, formulation, and address manager

Keyword Arguments

  • use_gpu::Bool=false: Use GPU linear solver
  • ordering::Symbol=:AMD: KLU fill-reducing ordering (:AMD, :COLAMD, :natural)
  • status: Model status dict used by both the residual and the Jacobian, owned by the workspace (default: build_status_dict(prob.sys), a copy of the system's status); change it to apply outages without modifying the system
  • verbose::Bool=false: Print detailed setup progress

Returns

  • NewtonWorkspace: Pre-allocated workspace ready for allocation-free iterations

Example

# Create power flow problem with formulation

# One-time setup with timing details
workspace = setup_powerflow_newton(prob; verbose=true)

# Multiple solves (fast, no setup overhead!)

sol2 = solve_powerflow_newton!(workspace, initial_guess_2; abstol=1e-10)

# Benchmark iterations precisely (excludes setup)

y0 = copy(workspace.iter_dae.y)
@btime solve_powerflow_newton!($workspace, $y0; abstol=1e-8, verbose=false)

See Also

  • solve_powerflow_newton!: Allocation-free iteration function
  • solve: High-level API with algorithm presets

PowerfulPF.solve_powerflow_newton! — Method
solve_powerflow_newton!(workspace::NewtonWorkspace, initial_guess::Vector; kwargs...)
    -> PowerFlowSolution

Solve power flow using pre-allocated workspace (allocation-free iterations).

This function performs ONLY Newton-Raphson iterations, assuming all setup has been done via setup_powerflow_newton. All buffers are pre-allocated, making this suitable for:

  • Precise iteration benchmarks (excludes setup overhead)
  • Multiple solves with different initial conditions
  • Repeated solves in optimization loops

Arguments

  • workspace::NewtonWorkspace: Pre-allocated workspace from setup_powerflow_newton
  • initial_guess::Vector: Initial guess for all variables. IMPORTANT: Must be a copy of workspace.iter_dae.y or your custom guess. Do NOT pass the workspace vector directly as it will be mutated during iterations

Keyword Arguments

  • abstol::Real=1e-8: Absolute tolerance for residual norm
  • maxiters::Int=50: Maximum Newton iterations
  • damping::Real=1.0: Step size damping factor (0.5 for cautious, 1.0 for full Newton)
  • jacobian_every::Int=1: Refresh the Jacobian every N iterations (N>1: dishonest Newton)
  • verbose::Bool=false: Print iteration details with timing

Returns

  • PowerFlowSolution: Solution object with convergence status and results

Example

# One-time setup
prob = ACPowerFlowProblem(sys)
workspace = setup_powerflow_newton(prob; verbose=true)

# IMPORTANT: Copy the initial guess (workspace vectors are mutated during solve)
y0 = copy(workspace.iter_dae.y)

# Solve with different tolerances (fast, no setup overhead!)
sol_loose = solve_powerflow_newton!(workspace, y0; abstol=1e-6)
sol_tight = solve_powerflow_newton!(workspace, y0; abstol=1e-10)

# Try different initial conditions
y0_perturbed = y0 .* 1.05  # 5% perturbation
sol_perturbed = solve_powerflow_newton!(workspace, y0_perturbed; abstol=1e-8)

# Benchmark iterations only (excludes setup)
using BenchmarkTools
@btime solve_powerflow_newton!($workspace, $y0; abstol=1e-8, verbose=false)

Notes

  • Uses DAE accessor functions to be future-proof when state variables are added
  • All iteration buffers pre-allocated in workspace (allocation-free after warmup)
  • Linear solver factorization cached and reused across iterations

See Also

  • setup_powerflow_newton: One-time setup function
  • solve: High-level API (recommended for most users)
  • NewtonWorkspace: Workspace structure documentation

For repeated solves, workspace can be reused with different initial conditions.

PowerfulPF.build_B_from_incidence — Method
build_B_from_incidence(A::SparseMatrixCSC{Int8}, b::Vector{T}) where T

Build bus susceptance matrix B = Aᵀ D A using COO format.

Arguments

  • A::SparseMatrixCSC{Int8}: Branch-bus incidence matrix (L×N)
  • b::Vector{T}: Branch susceptances (length L), where b[l] = 1/x_l

Returns

SparseMatrixCSC{T}: Bus susceptance matrix (N×N)

Algorithm

Uses COO format to avoid intermediate allocations:

For each branch l from bus i to bus j:
    B[i,i] += b_l
    B[j,j] += b_l
    B[i,j] -= b_l
    B[j,i] -= b_l

This is equivalent to B = Aᵀ diag(b) A but without allocating the L×N intermediate.

dc_bus_injections(sys::SystemModel) -> Vector{Float64}

Net active power injection (pu) at each internal bus index in the DC model: PV pg, minus PQ pl·f(vm) + ip·vm + yp·vm² (dc_load_power) and the conductance g·vm² of every fixed shunt model (dc_shunt_power, fixed_shunt_models; a switched shunt has none) at the case bus voltage vm, over in-service devices. The slack generator is not included; the reference bus absorbs the mismatch. Same injections as the DCPowerFlow model kernels.

MultiIslandSolution{T}

PowerfulPF.PowerFlowSolution — Type
PowerFlowSolution{T, PROB, DAE_T}

Result from power flow calculation.

Contains:

  • Solution state (converged, iterations, residual)
  • Reference to problem (for system access)
  • Reference to DAE (for variable access)
  • Lazy-computed observations (e.g., generator residuals)

Fields

  • converged::Bool: Whether the solver converged
  • residual_norm::T: Final residual norm (||g||∞)
  • iterations::Int: Number of iterations taken
  • retcode::Any: Return code from solver
  • stats::Any: Solver statistics (timing, etc.)
  • prob::PROB: Reference to the problem (ACPowerFlowProblem)
  • dae::DAE_T: Reference to workspace DAE (enables sol.dae.y access)

Usage

prob = ACPowerFlowProblem(sys)
sol = solve(prob, Newton())

if sol.converged
    # Access solution variables
    v = get_var(sol, :Bus, :v, 1)

    # Access raw state vector
    y = sol.dae.y
end

Lazy Evaluation

Generator residuals are lazily computed and cached on first access. This avoids unnecessary computation when these values aren't needed.

DAE Reference

The dae field stores a reference to the workspace DAE from the solver. This enables efficient access to the solution state vector (sol.dae.y) for TDS initialization. Since it's a reference, memory overhead is minimal (~8 bytes).
