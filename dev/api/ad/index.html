Core: Jacobians and Newton (PowerfulCore)

Jacobian sparsity detection, automatic differentiation backends and caches, and the Newton engine with its linear solver interface. These names are defined in PowerfulCore and PowerfulCore.DAEInfra.

Sparsity Detection

PowerfulCore.DAEInfra.PrecomputedSparsityDetector — Type
PrecomputedSparsityDetector(pattern::AbstractSparseMatrix)

Custom sparsity detector for DifferentiationInterface.jl that uses a pre-computed sparsity pattern instead of automatic tracing.

This provides a ~38x speedup over TracerSparsityDetector by using the fast jacobian_sparsity_pattern() function which analyzes model structure directly.

Performance Comparison (ACTIVSg 70k bus system)

  • TracerSparsityDetector(): ~4.5 seconds
  • PrecomputedSparsityDetector(): ~0.12 seconds (38x faster!)

Example

using DifferentiationInterface
using DifferentiationInterface: AutoSparse
using ADTypes: AutoForwardDiff
using SparseMatrixColorings: GreedyColoringAlgorithm

# Fast sparsity detection from model structure
sparsity = jacobian_sparsity_pattern(sys)

# Create custom detector
detector = PrecomputedSparsityDetector(sparsity)

# Use with DifferentiationInterface
backend = AutoSparse(
    AutoForwardDiff();
    sparsity_detector = detector,  # Use our fast detector!
    coloring_algorithm = GreedyColoringAlgorithm()
)

# Prepare and compute Jacobian as usual
prep = prepare_jacobian(residual!, zero(g), backend, zero(y))
jacobian!(residual!, g, J, prep, backend, y)

See Also

  • jacobian_sparsity_pattern: Computes sparsity from model structure (fast)
  • TracerSparsityDetector: Automatic tracing (slow but fully automatic)

PowerfulCore.DAEInfra.instance_residual_rows — Method
instance_residual_rows(am, sys, formulation, model_name; include_differential=false)
    -> Matrix{Int}

Rows of the DAE residual [f; g] that each instance of model_name writes: column i holds those of instance i (0 where the instance is not delivered through the residual), one row per residual of the model: its differential residuals (rows 1:n_diff, only with include_differential) and its algebraic residuals (offset by n_diff), including shared residuals such as bus balances.

A quantity read only by the equations of one instance (its parameters and setpoints) enters exactly these rows.

source
PowerfulCore.ADCacheCore — Type
ADCacheCore{F}

Shared state for all autodiff cache backends.

Contains the common fields needed by both ForwardDiffCache and EnzymeCache:

  • System model reference
  • Formulation trait
  • Address manager
  • Float64 workspace (used by all backends)

Type Parameters

  • F: FormulationTrait type (PowerInjection or CurrentInjection)

Type Erasure Note

The sys field is typed as Any rather than SystemModel to prevent excessive compile-time type specialization. Since SystemModel contains model-specific types in its models::NamedTuple, specializing on sys would create separate compiled versions of ADCacheCore for every unique model combination. The runtime cost of one dynamic dispatch is negligible (~nanoseconds) compared to avoiding combinatorial compilation times.

All accessor functions use type barriers (e.g., ::SystemModel) to restore type stability at the call site.

source
PowerfulCore.AbstractADCache — Type
AbstractADCache{F}

Abstract type for autodiff caches.

All cache types must implement:

  • Callable interface: cache(g, y, status, t) for power flow
  • Callable interface: cache(f, g, x, y, status, t) for TDS

t is the time of the state and has no default: a model's residuals can depend on it directly (not only through the state), so every caller states it.

Concrete subtypes:

  • ForwardDiffCache: ForwardDiff with Dual workspace caching
  • EnzymeCache: Enzyme with Float64-only path

PowerfulCore.prepare_sparse_jacobian — Method
prepare_sparse_jacobian(f!, y, x, adcache, contexts...; include_differential=false, strict=Val(true),
                        sparsity=nothing) -> (J, backend, prep)

Set up a sparse Jacobian of f!(y, x, contexts...) over the DAE variables of adcache (contexts: DifferentiationInterface contexts, e.g. Constant(t) for the time of the state, passed to jacobian! in the same types): the sparsity pattern from the model structure (jacobian_sparsity_pattern, or the given sparsity), a Float64 Jacobian with that pattern, the DifferentiationInterface backend for the cache's AD backend, and the prepared DI extras. For a GPU system the pattern and Jacobian are device sparse matrices (device_sparse), so the Jacobian is decompressed on the GPU.

y and x are passed to prepare_jacobian as given; their types must match the arrays used later in jacobian! (e.g. a view stays a view). Pass sparsity to share one pattern across several preparations (e.g. per-thread workspaces).

PowerfulCore.ForwardDiffCache — Type
ForwardDiffCache{F} <: AbstractADCache{F}

ForwardDiff-based autodiff cache with Dual workspace caching.

Pre-allocates Float64 workspace and caches Dual workspaces on demand. This avoids the overhead of creating new workspaces on every Jacobian evaluation (typically ~1ms per allocation for large systems).

Zero allocation: After warmup (first call per unique Dual type)

Type Parameters

  • F: FormulationTrait type (PowerInjection or CurrentInjection)

Fields

  • core::ADCacheCore{F}: Shared state (sys, formulation, addressmanager, floatws)
  • dual_workspaces::Dict{DataType, SystemBuffers}: Cached Dual workspaces
  • tds_dual_buffers::Dict{DataType, NamedTuple}: TDS-specific Dual buffers
  • empty_vecs::Dict{DataType, Tuple{Vector, Vector}}: Cached empty (f, x) vectors per Dual type
  • parameter_fields::Dict{Symbol, Vector{Symbol}}: Model fields that every Dual workspace reads from its own copy of its element type (see register_parameter_fields!)

Example

# Create via factory function (recommended)
adcache = create_adcache(am, sys, formulation, ForwardDiffBackend())

# Use as callable
adcache(g, y)        # Power flow
adcache(f, g, x, y)  # TDS

PowerfulCore.get_typed_workspace! — Method
get_typed_workspace!(cache::ForwardDiffCache, ::Type{T}) -> SystemBuffers

Workspace for element type T. For Float64, the cache's Float64 workspace. For Dual types, a workspace cached per T, created on first use with every setpoint copied from the Float64 workspace, and the modes and discrete quantities of its automata shared with their memory copied (see AutomatonState(state, T)), so Dual evaluation computes the same residual function (setpoints such as time constants or references are not left at zero). Its evaluators read the registered parameter fields (register_parameter_fields!) from copies of element type T, initialized from the system.

PowerfulCore.register_parameter_fields! — Method
register_parameter_fields!(cache::ForwardDiffCache, model_name::Symbol, fields)

Give the fields fields of model model_name a copy of element type T in every Dual workspace T of cache, so that parameter values of that type (e.g. Dual numbers of a parameter Jacobian) can be written there without changing the system. Dual workspaces built before are dropped and rebuilt on first use.

The copies take their values from the system when a workspace is built; write the fields through scatter_parameters!, which updates the copies too.

PowerfulCore.EnzymeCache — Type
EnzymeCache{F} <: AbstractADCache{F}

Enzyme-based autodiff cache with Float64-only path.

Always uses Float64 - Enzyme handles derivatives via LLVM transformation and shadow arrays, not Dual numbers.

Zero allocation: Immediately (no warmup needed)

Type Parameters

  • F: FormulationTrait type (PowerInjection or CurrentInjection)

Fields

  • core::ADCacheCore{F}: Shared state (sys, formulation, addressmanager, floatws)
  • empty_f::Vector{Float64}: Pre-allocated empty vector for power flow (avoids allocation in differentiated code)
  • empty_x::Vector{Float64}: Pre-allocated empty vector for power flow (avoids allocation in differentiated code)

Example

# Create via factory function (recommended)
adcache = create_adcache(am, sys, formulation, EnzymeBackend())

# Use as callable
adcache(g, y)        # Power flow
adcache(f, g, x, y)  # TDS

Usage with DifferentiationInterface

using DifferentiationInterface: AutoSparse
using ADTypes: AutoEnzyme
using Enzyme

# IMPORTANT: Use function_annotation=Duplicated to properly shadow the functor
backend = AutoSparse(
    AutoEnzyme(; mode=Enzyme.Forward, function_annotation=Enzyme.Duplicated);
    sparsity_detector = PrecomputedSparsityDetector(sparsity),
    coloring_algorithm = GreedyColoringAlgorithm()
)

prep = DifferentiationInterface.prepare_jacobian(adcache, g, backend, y)
DifferentiationInterface.jacobian!(adcache, g, J, prep, backend, y)

Implementation Notes

Enzyme works at the LLVM level:

  • Forward mode: Uses (x, dx) pairs where both are Float64
  • The workspace stays Float64 - no SystemBuffers{Dual} needed
  • DifferentiationInterface handles shadow array management
  • Important: Empty vectors for f/x are pre-allocated because Enzyme cannot differentiate through array allocations inside the target function

Newton Solver

PowerfulCore.BUS_VOLTAGE_STEP_LIMIT — Constant
BUS_VOLTAGE_STEP_LIMIT

The step limit (NewtonPolicy max_step, 0.5 pu or rad) of the Newton iterations on bus voltages in polar form (the reinitialization of the phasor simulation and the algebraic solve of the Y-bus integrations), which also keep the voltage magnitudes positive (positive, see NewtonPolicy). At a bus whose voltage is near zero the column of the Jacobian for its angle is proportional to the voltage, and an unlimited Newton step in the angle is whole turns long, to a root that is the same modulo 2π; a voltage that crosses zero reaches the other solution of the polar equations, (-v, θ + π).

PowerfulCore.NewtonPolicy — Type
NewtonPolicy(; jacobian_every=1, stall_ratio=Inf, stall_reused_only=false, reuse_jacobian=false,
               max_step=Inf, positive=Int[], positive_fraction=0.001, damping=1.0, max_tries=8,
               backtrack_factor=0.5, merit_norm=Inf, sufficient_decrease=0.0, strict_search=false)

Iteration policy for newton_solve!.

  • jacobian_every: refresh the Jacobian every k iterations (1 = full Newton,

    1 = "dishonest"/modified Newton reusing the factorization in between).

    The Jacobian is always refreshed on the first iteration, unless reuse_jacobian.
  • stall_ratio: also refresh when ‖g‖∞ > stall_ratio · ‖g_prev‖∞ (an iteration that contracts too little); with stall_reused_only, only after an iteration that reused a Jacobian taken at an earlier iterate (a chord iteration), not after one with the Jacobian at its own iterate.
  • reuse_jacobian: the first iteration of a call uses the factorization the solver holds from an earlier call (a chord Newton across calls) and refreshes only where it holds none. The caller discards it (reset_factorization!) where the equations changed.
  • max_step: trust region; the Newton step is scaled so ‖Δy‖∞ ≤ max_step.
  • positive: indices of variables that stay positive (bus voltage magnitudes): a trial point is clipped so that each of them remains above positive_fraction of its value before the step (a variable that crosses zero reaches another solution of equations polar in it, with the opposite sign). Applies to variables that are positive at the start of the iteration.
  • damping: constant factor applied to every step.
  • max_tries: backtracking line search trials (step halved by backtrack_factor each time); a trial is accepted when ‖g‖ falls below (1 - sufficient_decrease · α) ‖g_prev‖ (α the fraction of the step taken) in the norm merit_norm (Inf, or 2, the merit function along which the Newton step is a descent direction). max_tries=1 takes the (damped, limited) step as is.
  • strict_search: where no trial is accepted, the iterate stays and the Jacobian is taken again at the next iteration (status :stalled if it was taken at this iterate); otherwise the last trial is accepted regardless.

PowerfulCore.factorize! — Function
factorize!(solver::AbstractNewtonLinearSolver, J) -> solver

Factorize the sparse matrix J into solver. The first call, and the first after reset_factorization!, performs the symbolic analysis and the numeric factorization with pivoting; later calls reuse the symbolic analysis and the pivots and only refactorize numerically, so J must keep the same sparsity pattern and numerical structure (otherwise call reset_factorization! first). A singular J throws.

PowerfulCore.newton_solve! — Method
newton_solve!(residual!, jacobian!, y, bufs, solver, policy; abstol, maxiters,
              catch_linear_failure=false, verbose=false, history=nothing,
              fresh_jacobian=false, refresh_due=false)
    -> (converged, status, iterations, steps, residual_norm, refresh_due)

Solve g(y) = 0 in place starting from y, with residual!(g, y) and jacobian!(J, y). Convergence is ‖g‖∞ < abstol at the start of an iteration, or after the last step. The residual last evaluated is that at y where the solve converged.

status is :converged, :maxiters, :diverged (non-finite residual or iterate), :stalled (policy.strict_search: no decrease along the step of a Jacobian taken at the iterate) or :singular (linear solve threw; only with catch_linear_failure=true, otherwise the exception propagates). iterations counts the iterations begun (the one that finds the residual below abstol included), steps the steps taken.

The solver's factorization is reused across calls where policy.reuse_jacobian. A step that reused the Jacobian and contracted the residual by less than policy.stall_ratio leaves refresh_due true: the Jacobian is taken again at the next iteration, of this call or, passed as refresh_due to the next call, of that one. fresh_jacobian: the caller took the factorization held at y (a Jacobian just taken is not taken again for a stall). Call reset_factorization!(solver) for a fresh symbolic analysis. history, a vector, receives the residual norm at the start and after each accepted step.

source
PowerfulCore.reset_factorization! — Function
reset_factorization!(solver::AbstractNewtonLinearSolver) -> solver

Discard the cached factorization, so the next factorize! is a full one: a fresh symbolic analysis and a numeric factorization with pivoting. Needed when the sparsity pattern of the matrix changes, and where its numerical structure may have (its equations changed, so that a nonzero of a row can move off the entry an earlier factorization pivoted on): a refactorization reuses the pivots of the last full factorization, which can then be zero or unstable, and a matrix that is singular throws there all the same.
