Core: Time Series and Injection Recording (PowerfulCore)

Time series solutions of time-domain simulations and the recording of per-model contributions to shared residuals. These names are defined in PowerfulCore.DAEInfra and exported by PowerfulCore.

Time Series Solutions

PowerfulCore.DAEInfra.TDSSolution — Type
TDSSolution{SOL, T, SYS, AM}

Unified solution type for time-domain simulation results.

Works for both TDS (DiffEq ODESolution) and Ybus (trapezoidal) solvers. Provides ergonomic get_series(sol, :Model, :var, key) API without needing the problem object.

Type Parameters

  • SOL: ODESolution type (for TDS) or Nothing (for Ybus)
  • T: Numeric type (typically Float64)
  • SYS: SystemModel type
  • AM: AddressManager type

Fields

  • sol: ODESolution (TDS) or nothing (Ybus)
  • t: Time vector (Ybus only) or nothing (TDS uses sol.t)
  • u: State matrix (Ybus only) or nothing (TDS uses sol.u)
  • retcode: Solution status (:Success, :MaxIters, etc.)
  • n_diff: Number of differential states
  • n_alg: Number of algebraic states
  • sys: SystemModel reference (for external key lookups)
  • address_manager: AddressManager reference (for address lookups)

Example

# Get time series for bus voltage
t, v = get_series(sol, :Bus, :v, 5001)

# Interpolation (TDS only)
state_at_0_5 = sol(0.5)

# Access time vector
t = sol.t

# Index into timesteps
u_at_step_10 = sol[10]

PowerfulCore.DAEInfra.get_series — Method
get_series(sol::TDSSolution, model::Symbol, var::Symbol, ext_key) -> (t, values)

Extract a time series for a specific variable from the solution.

This is the primary API for extracting simulation results. It handles:

  1. External key → internal index conversion
  2. Variable type detection (StateVar vs AlgebVar)
  3. Address calculation with proper offset
  4. Value extraction from either TDS or Ybus storage format

Arguments

  • sol::TDSSolution: The simulation solution
  • model::Symbol: Model name (e.g., :Bus, :GENROU)
  • var::Symbol: Variable name (e.g., :v, :delta, :omega)
  • ext_key: External key (e.g., 5001 or (5001,) for buses)

Returns

  • (t, values): Tuple of time vector and value vector

Example

# Get bus voltage
t, v = get_series(sol, :Bus, :v, 5001)

# Get generator rotor angle (key is a tuple for generators)
t, delta = get_series(sol, :GENROU, :delta, (101, "1"))

# Plot results
using Plots
plot(t, v, label="Bus 5001 voltage")

PowerfulCore.DAEInfra.get_series — Method
get_series(sol::TDSSolution, model::Symbol, var::Symbol) -> NamedTuple

Extract time series for ALL instances of a variable from the solution.

Returns a NamedTuple with t (time vector) and one column per instance, named {Model}_{var}_{external_key}.

Arguments

  • sol::TDSSolution: The simulation solution
  • model::Symbol: Model name (e.g., :Bus, :GENROU)
  • var::Symbol: Variable name (e.g., :v, :delta, :omega)

Returns

NamedTuple with fields:

  • t: Time vector
  • {Model}_{var}_{key}: One field per instance

Example

# Get all bus voltages
data = get_series(sol, :Bus, :v)
# Returns (t=..., Bus_v_1=..., Bus_v_2=..., Bus_v_3=..., ...)

# Plot all voltages
using Plots
plot(data.t, [data[k] for k in keys(data) if k != :t])

# Convert to DataFrame
using DataFrames
df = DataFrame(data)

See Also

  • get_series(sol, model, var, ext_key) - Extract single variable

Injection Recording

PowerfulCore.DAEInfra.InjectionMonitor — Type
InjectionMonitor{K}

Specifies which SharedRes addresses to monitor.

Type Parameters

  • K: External key type (e.g., Int for bus numbers)

Example

# Monitor the active and reactive power balance of buses 1, 2, 3 (K = Tuple{Int})
monitor = InjectionMonitor(
    :Bus => [:p => [(1,), (2,), (3,)], :q => [(1,), (2,), (3,)]]
)
source
PowerfulCore.DAEInfra.InjectionRecorder — Type
InjectionRecorder{T, K}

Records per-model contributions to monitored SharedRes addresses.

Uses a two-phase recording approach:

  1. record_model_contributions! caches values in pending (called many times per step)
  2. commit_contributions! pushes pending to timeseries (called once per accepted step)

Type Parameters

  • T: Numeric type (Float64, etc.)
  • K: External key type (Int for bus numbers, etc.)

Fields

  • monitor: What addresses are being monitored
  • address_map: Pre-computed contributor mappings
  • pending: Cached values from latest evaluation (not yet committed)
  • contributions: Time series storage (target => model => values)
  • timestamps: Time points recorded (one per accepted step)
source
PowerfulCore.DAEInfra.InjectionRecorder — Method
InjectionRecorder(monitor::InjectionMonitor{K}, sys_ws, sys, am) where K

Advanced constructor, for a caller that already has a SystemBuffers and does not want one built from a TDSProblem. Most callers use InjectionRecorder(monitor, prob::TDSProblem) instead.

Extended help

  • monitor: InjectionMonitor specifying which addresses to track
  • sys_ws: SystemBuffers (provides model workspaces and metadata)
  • sys: SystemModel (provides index order for key lookups)
  • am: AddressManager (provides DAE address mappings)

PowerfulCore.DAEInfra.commit_contributions! — Method
commit_contributions!(recorder, t)

Commit cached pending values to the timeseries at time t.

This should be called once per accepted step (via a callback), not during every residual evaluation. This ensures the timeseries contains exactly one entry per accepted step with the converged values.

PowerfulCore.DAEInfra.record_model_contributions! — Method
record_model_contributions!(recorder, model_name, ws, t, active_mask)

Cache contributions from a model's workspace into the pending buffer.

This function is called at every evaluate_system_residuals! invocation (including Newton iterations). Values are cached in pending and will be committed to the timeseries when commit_contributions! is called at accepted steps.

Arguments

  • recorder: InjectionRecorder to store contributions
  • model_name: Symbol identifying the model
  • ws: ResidualBuffers workspace
  • t: Current time
  • active_mask: Vector{Bool} indicating active status (passed from caller)
source
PowerfulCore.DAEInfra.InjectionRecorder — Method
InjectionRecorder(monitor::InjectionMonitor{K}, prob::TDSProblem) where K

Convenience constructor that creates recorder from TDSProblem. Creates a temporary SystemBuffers internally for address mapping setup.

Arguments

  • monitor: InjectionMonitor specifying which addresses to track
  • prob: TDSProblem (provides sys, address_manager, and formulation)

Example

bus_keys = [(i,) for i in tds_prob.sys.models.Bus.i]
monitor = InjectionMonitor(:Bus => [:p => bus_keys, :q => bus_keys])
recorder = InjectionRecorder(monitor, tds_prob)
sol = solve(tds_prob; recorder=recorder)
