Dynamic Models (PowerfulTDS)

Dynamic models for time-domain simulation, parsed from PSS/E DYR files with parse_dynamics. Generators and converter models replace the power flow generator with the same bus number and ID; exciters, governors and electrical controllers attach to the device they control. Import model types from Powerful.Models.

Synchronous Generators

PowerfulTDS.GENCLS — Type
GENCLS{T} <: AbstractModel

Classical synchronous machine: a constant internal voltage E_q behind the transient impedance r_a + j xd_p, with the swing equation for the rotor.

A GENCLS record replaces the power flow generator (PV or Slack) with the same bus number and ID. xd_p and r_a are inherited from that generator's source impedance (zx, zr); the DYR record supplies H and D.

Parameters

  • BUS: bus number of the generator
  • ID: generator ID (up to two characters)
  • H: inertia constant (s, MW·s/MVA)
  • D: damping coefficient (pu)
  • xd_p: d-axis transient reactance (pu)
  • r_a: armature resistance (pu)
  • status: true when in service

Equations

  • dδ/dt = ω_b (ω - 1), with ω_b the system base angular frequency
  • 2H dω/dt = P_m - P_e - D (ω - 1)

Variables

  • States: delta (rotor angle, rad), omega (rotor speed, pu)
  • Algebraic: E_q (internal voltage, receives the exciter contribution), P_m (mechanical power, receives the governor contribution)
  • Observables: P_e, Q_e (electrical power output)

Without an exciter or governor, E_q and P_m stay at their initial values. Initialization computes delta, E_q and P_m from the power flow voltage and the replaced generator's output, with omega = 1.

source
PowerfulTDS.GENROU — Type
GENROU{T} <: AbstractModel

Round rotor synchronous machine with quadratic saturation: two rotor circuits on each axis (transient and subtransient), with equal d- and q-axis subtransient reactances (X''q = X''d).

A GENROU record replaces the power flow generator (PV or Slack) with the same bus number and ID. The armature resistance ra is inherited from that generator's source resistance (zr).

Parameters

  • BUS, ID: bus number and generator ID
  • Td10, Td20: d-axis transient and subtransient open-circuit time constants (s)
  • Tq10, Tq20: q-axis transient and subtransient open-circuit time constants (s)
  • H: inertia constant (s); D: damping coefficient (pu)
  • Xd, Xq: d- and q-axis synchronous reactances (pu)
  • Xd1, Xq1: d- and q-axis transient reactances (pu)
  • Xd2: subtransient reactance (pu), used on both axes
  • Xl: leakage reactance (pu)
  • S10, S12: saturation factors at 1.0 and 1.2 pu flux; the quadratic saturation function acts on the subtransient air-gap flux magnitude
  • ra: armature resistance (pu)
  • status: true when in service

Variables

  • States: delta (rotor angle, rad), omega (rotor speed, pu), e1q, e1d (q- and d-axis transient voltages), e2d, e2q (d- and q-axis subtransient voltages)
  • Algebraic: Id, Iq (armature currents in the rotor frame), E_fd (field voltage, receives the exciter contribution), P_m (mechanical power, receives the governor contribution)
  • Observables: Pe, Qe (electrical power output)

The swing equation is 2H dω/dt = P_m - τ_e - D (ω - 1) with the air-gap torque τ_e. Without an exciter or governor, E_fd and P_m stay at their initial values.

PowerfulTDS.GENSAL — Type
GENSAL{T} <: AbstractModel

Salient pole synchronous machine with quadratic saturation on the d axis: a field and a damper circuit on the d axis and one subtransient circuit on the q axis.

A GENSAL record replaces the power flow generator (PV or Slack) with the same bus number and ID. The armature resistance ra is inherited from that generator's source resistance (zr).

Parameters

  • BUS, ID: bus number and generator ID
  • Td10, Td20: d-axis transient and subtransient open-circuit time constants (s)
  • Tq20: q-axis subtransient open-circuit time constant (s)
  • H: inertia constant (s); D: damping coefficient (pu)
  • Xd, Xq: d- and q-axis synchronous reactances (pu)
  • Xd1: d-axis transient reactance (pu)
  • Xd2: d-axis subtransient reactance (pu); the q-axis one is not a parameter: Xq'' = Xd'' (PSS/E GENSAL)
  • Xl: leakage reactance (pu)
  • S10, S12: saturation factors at 1.0 and 1.2 pu flux; the quadratic saturation function acts on e1q
  • ra: armature resistance (pu)
  • status: true when in service

Variables

  • States: delta (rotor angle, rad), omega (rotor speed, pu), e1q (q-axis transient voltage), psi1d (d-axis damper flux), psi2q (q-axis subtransient flux)
  • Algebraic: Id, Iq (armature currents in the rotor frame), E_fd (field voltage, receives the exciter contribution), P_m (mechanical power, receives the governor contribution)
  • Observables: Pe, Qe (electrical power output)

PowerfulTDS.GENTPJ1 — Type
GENTPJ1{T} <: AbstractModel

Round rotor synchronous machine (GENTPJ1): the GENROU structure with separate d- and q-axis subtransient reactances and a saturation input that includes the armature current, ψ'' + Kis |I|. q-axis saturation is the d-axis value scaled by Xq/Xd.

A GENTPJ1 record replaces the power flow generator (PV or Slack) with the same bus number and ID. The armature resistance ra is inherited from that generator's source resistance (zr).

Parameters

  • BUS, ID: bus number and generator ID
  • Td10, Td20: d-axis transient and subtransient open-circuit time constants (s)
  • Tq10, Tq20: q-axis transient and subtransient open-circuit time constants (s)
  • H: inertia constant (s); D: damping coefficient (pu)
  • Xd, Xq: d- and q-axis synchronous reactances (pu)
  • Xd1, Xq1: d- and q-axis transient reactances (pu)
  • Xd2, Xq2: d- and q-axis subtransient reactances (pu)
  • Xl: leakage reactance (pu)
  • S10, S12: saturation factors at 1.0 and 1.2 pu flux
  • Kis: armature current multiplier in the saturation input
  • ra: armature resistance (pu)
  • status: true when in service

Variables

  • States: delta, omega, e1q, e1d, e2d, e2q (as in GENROU)
  • Algebraic: Id, Iq, E_fd, P_m
  • Observables: Pe, Qe

Exciters

PowerfulTDS.SEXS — Type
SEXS{T} <: AbstractModel

Simplified excitation system (SEXS). Controls the field voltage E_fd of the generator with the same bus number and ID (any model of the :generators group).

The voltage error vref - v (with v the terminal bus voltage magnitude) passes through a lead-lag (1 + s TA)/(1 + s TB), with TA = TATB · TB, and a lag K/(1 + s TE) with anti-windup limits [EMIN, EMAX], whose output is E_fd.

Parameters

  • BUS, ID: bus number and ID of the controlled generator
  • TATB: ratio TA/TB of the lead-lag
  • TB: lag time constant of the lead-lag (s)
  • K: gain (pu)
  • TE: exciter time constant (s)
  • EMIN, EMAX: field voltage limits (pu)
  • status: true when in service

Variables

  • States: LL_x (lead-lag state), LAW_y (exciter output)
  • Algebraic: vref (voltage reference, held at its initial value), E_fd (field voltage)
  • External: v (terminal bus voltage magnitude)

Initialization sets E_fd to the generator's initial field voltage and vref = v + E_fd/K.

Governors

PowerfulTDS.TGOV1 — Type
TGOV1{T} <: AbstractModel

Steam turbine governor (TGOV1). Controls the mechanical power P_m of the generator with the same bus number and ID (any model of the :generators group).

The speed deviation ω - 1 is subtracted from the power reference pref and scaled by 1/R; a first-order lag 1/(1 + s T1) with anti-windup limits [Vmin, Vmax] gives the valve position; a lead-lag (1 + s T2)/(1 + s T3) gives the turbine power, from which the damping term Dt (ω - 1) is subtracted. The result, pout, is the generator's mechanical power.

Parameters

  • BUS, ID: bus number and ID of the controlled generator
  • R: speed droop (pu)
  • T1: governor lag time constant (s)
  • T2: lead time constant (s)
  • T3: lag time constant (s)
  • Dt: turbine damping coefficient (pu)
  • Vmax, Vmin: valve position limits (pu)
  • status: true when in service

Variables

  • States: LAG_y (valve position), LL_x (lead-lag state)
  • Algebraic: pref (power reference, held at its initial value), pout (turbine output power)
  • External: omega (speed of the controlled generator)

Initialization sets pout to the generator's initial mechanical power and the reference to R times it, which holds the governor at rest at synchronous speed: it reads the generator's initial speed and refuses a start at any other.

PowerfulTDS.REECA1 — Type
REECA1{T} <: AbstractModel

Renewable energy electrical control model A (REECA, WECC 2014), generated. Computes the current commands Ipcmd and Iqcmd of the converter model with the same bus number and ID (any model of the `:rengengroup, such as [REGCA1](@ref)) from active and reactive power references, the terminal voltage, and the electrical and reactive power the converter delivers (itsPeandQe, measured as REECA1'sPeandQgen`).

Features: reactive power or power factor reference (PFFLAG), reactive power PI control (VFLAG), voltage PI control (QFLAG), non-windup PI controllers, the voltage dip state machine (the reactive current injection Kqv · (voltage error) outside the deadband [dbd1, dbd2] during a dip, the controllers and the power order frozen, and the Thld and Thld2 holds after it), rate-limited active power reference, the power order within [PMIN, PMAX] with anti-windup, voltage-dependent current limits (VDL1 and VDL2) and P or Q priority current limiting (PQFLAG). The limits, the dip logic and the holds are automata, whose transitions the simulation locates.

Parameters

  • BUS, ID: bus number and ID of the controlled converter model
  • VREG: remote voltage regulation bus; stored, the terminal bus voltage is used
  • Flags (each 0 or 1, of the parameters' element type): PFFLAG (1 = power factor control, 0 = Q control), VFLAG (1 = Q control, 0 = voltage control), QFLAG (1 = voltage or Q control, 0 = constant power factor or Q), PFLAG (1 = speed dependent active power reference), PQFLAG (0 = Q priority, 1 = P priority)
  • Voltage dip: Vdip, Vup (dip thresholds, pu), Trv (voltage filter time constant, s), dbd1, dbd2 (deadband), Kqv (reactive current injection gain), Iqh1, Iql1 (injection limits), Vref0 (voltage reference; 0 uses the initial filtered voltage)
  • After a dip: Thld (the injection is held at Iqfrz for Thld s if Thld > 0, continues for -Thld s if Thld < 0, ends at once if 0), Thld2 (time Ipmax is held at its dip value, s)
  • Reactive power control: Tp (electrical power filter time constant, s), QMax, QMin (reactive power limits), VMAX, VMIN (voltage control limits), Kqp, Kqi (reactive power PI gains), Kvp, Kvi (voltage PI gains), Vref1 (voltage reference when VFLAG = 0), Tiq (reactive current filter time constant, s)
  • Active power control: dPmax, dPmin (power reference rate limits, pu/s), PMAX, PMIN (power order limits), Imax (apparent current limit), Tpord (power order time constant, s)
  • VDL1 (reactive current limit versus voltage): points (Vq1, Iq1) to (Vq4, Iq4)
  • VDL2 (active current limit versus voltage): points (Vp1, Ip1) to (Vp4, Ip4)
  • status: true when in service

Variables

  • States: s0_y (filtered voltage), S1_y (filtered electrical power), PIQ_xi, PIV_xi (PI integrators), s4_y (reactive current from the power factor path), pfilt_y (filtered power reference), s5_y (power order)
  • Algebraic: Pref, Qref, pfaref (references, held at their initial values), Qerr (reactive power error), Vsel (voltage reference of the voltage PI), Iqinj (reactive current injection of the dip logic), Iqmax, Ipmax (current limits; Iqmin = -Iqmax, Ipmin = 0), Ipcmd_out, Iqcmd_out (current commands)
  • External: v (terminal voltage magnitude), Pe and Qgen (the active and reactive power the converter delivers, its Pe and Qe)

Iqcmd_out follows the specification's sign: positive injects reactive power. REECA1 delivers -(Iqcmd_out - Iqcmd0) to the converter's Iqcmd, whose positive value absorbs. The power reference filter time constant is fixed at 0.02 s, and the speed used by the speed-dependent active power path is 1 pu.

The start is at rest: where the voltage PI is used (QFLAG = 1) the voltage, and where the Q PI is used (VFLAG = 1) Qgen, is within that controller's limits, unless the start is in a dip (where the controllers are frozen); a start outside them is refused.

PowerfulTDS.REGCA1 — Type
REGCA1{T} <: AbstractREGCA1

Renewable energy generator/converter model A (REGC_A, WECC 2014, section 3.2 and Appendix A), generated: a current source that turns the active and reactive current commands Ipcmd and Iqcmd into the power it delivers at its terminal, Pe and Qe. Used for wind and solar plants, driven by an electrical controller such as REECA1, which measures Pe and Qe.

A REGCA1 record replaces the power flow generator (PV or Slack) with the same bus number and ID. All parameters come from the DYR record; the data is checked where it enters (its divisors nonzero, and Zerox < Brkpt, Lvpnt0 < Lvpnt1, Rrpwr > 0, Iqrmax > 0, Iqrmin < 0, Iolim < 0).

The record is per unit on the converter's own MVA base Mbase, which is the MBASE of the generator it replaces: it is not a field of the model or of the record, and is carried by the system as the rating of the linked device (ModelRating(:mbase, NominalPower; from = LinkedDevice())). The states, Ipcmd, Iqcmd, Pe and Qe are on that base; the model converts to the system base Sbase only where it meets the network, with the derived ratio Mratio = Mbase/Sbase (RatingRatio), in its bus injections and in the division of the power flow's powers at the start.

Parameters

  • BUS, ID: bus number and generator ID
  • Lvplsw: low voltage power logic (LVPL) switch, 1 = LVPL acts, 0 = it does not
  • Tg: converter time constant of both current lags (s)
  • Rrpwr: up-ramp rate limit of the active current (pu/s)
  • Brkpt, Zerox: LVPL breakpoint and zero crossing (pu)
  • Lvpl1: LVPL at Brkpt (pu)
  • Volim: the voltage the high-voltage reactive current management keeps Vt at or below (pu)
  • Lvpnt1, Lvpnt0: voltages of the low-voltage active current management, which passes all of the active current above Lvpnt1 and none below Lvpnt0 (pu)
  • Iolim: the floor of the reactive power of the high-voltage management (pu)
  • Tfltr: time constant of the voltage filter that LVPL reads (s)
  • Khv, Accel: acceleration factors of an iterative network solution; read from the DYR record, with no effect on the simultaneous solution
  • Iqrmax, Iqrmin: rate limits of the reactive current (pu/s), the first acting where the initial reactive power is positive, the second where it is negative
  • status: true when in service

Variables

  • States: Vflt (filtered voltage), Ip (active current, its rise limited at Rrpwr, within LVPL), Iq_lag (reactive current, positive injecting)
  • Algebraic: Ipcmd, Iqcmd (current commands, held at their initial values plus the controller's contribution), dq (the reduction of the reactive power by the high-voltage management), Pe, Qe (the power injected into the bus, on the converter's base)
  • External: v (terminal voltage magnitude)

Pe = Ip · multp · v and Qe = max(Iq_lag · v - dq, Iolim), multp the low-voltage active current management. Its discrete behaviour is automata, whose transitions the simulation locates: iq_recovery (which rate limit of Iq_lag acts, chosen by the sign of the initial reactive power Qgen0), hv (the high-voltage management: dq holds Vt at Volim while the reactive power is above its floor) and Ip (the active current: free, rise-limited at Rrpwr, or held within LVPL, a non-windup upper limit that falls with the filtered voltage and carries Ip down with it). Iq_lag follows -Iqcmd, so a positive Iqcmd absorbs reactive power. A start the model does not have is refused: active power at or below Lvpnt0 other than zero, reactive power below Iolim, a voltage above Volim with the reactive power above its floor, or an active current above LVPL.

source
PowerfulTDS.REGFM_A1 — Type
REGFM_A1{T} <: AbstractModel

Droop-controlled grid-forming converter (WECC REGFMA1, PNNL-35110), generated: a voltage source behind the coupling reactance XL whose frequency follows the active power by the P-f droop mp and whose voltage follows the reactive power by the Q-V droop mq, with the voltage controller, the overload mitigation of the active power and the Qmax/Qmin controller of the reactive power. It belongs to the `:rengfm` group.

A REGFM_A1 record replaces the power flow generator (PV or Slack) with the same bus number and ID. The data is checked where it enters (flags 0 or 1, ordered limits, positive XL, ImaxF and integral gains, nonzero filter time constants).

The record is per unit on the converter's own MVA base Mbase, the MBASE of the generator it replaces, as REGCA1's is: it has no rating field, and the system carries the rating of the linked device and the derived ratio Mratio = Mbase/Sbase. The states, references, Pe and Qe are on the converter's base, and Mratio converts the bus injections and the power flow's powers at the start.

Parameters

  • BUS, ID: bus number and converter ID
  • XL: coupling reactance (pu)
  • mq: Q-V droop gain
  • kpv, kiv: gains of the voltage controller (VFlag = 1)
  • Emax, Emin: limits of the output of the voltage loop
  • mp: P-f droop gain
  • Pmax, Pmin: limits of the active power output (Pmin negative for storage)
  • kppmax, kipmax: gains of the overload mitigation controller
  • w0: rated angular frequency (rad/s)
  • TPf, TQf, TVf: time constants of the power and voltage measurement filters (s)
  • Qmax, Qmin: limits of the reactive power output
  • VFlag: 1 regulates the terminal voltage through the PI, 0 the internal voltage directly
  • QVFlag: 1 the plant controller changes Vref, 0 it changes Qref
  • kpqmax, kiqmax: gains of the Qmax and Qmin controller
  • ImaxF: maximum transient output current (pu)
  • status: true when in service

The record's fields follow the order of PNNL-35110 Table 1.

Variables

  • States: Pinv, Qinv, Vinv (filtered power and voltage), delta (angle of the internal voltage), xpmax, xpmin, xqmax, xqmin (limit controllers' integrators), xv (integrator of the voltage controller)
  • Algebraic: Pref, Qref, Vref (references the plant controller changes), Vcmd, Edroop, Idroop, Pe, Qe
  • External: v, theta (terminal voltage)

The integrators' limits, the voltage controller's, and the current limit are automata, whose transitions the simulation locates.

PowerfulTDS.VoltagePlayback — Type
VoltagePlayback{T} <: AbstractModel

A bus driven by a recorded voltage: it holds the magnitude and angle of its bus to recorded series V(t) and Θ(t) and supplies whatever power that takes, so that the devices at the bus can be simulated against measurements (playback validation).

It replaces the power flow Slack unit with the same bus number and ID, as a dynamic generator replaces its Slack or PV unit. Every Slack unit at its bus must be replaced (by it or by the dynamic models of the other units); a unit left in place would hold the bus voltage too. It has no DYR record: build it with VoltagePlayback(bus; id, t, v, theta, breaks) and add it to the dynamic models, merge(dyr, (VoltagePlayback = StructArray([pb]),)).

Parameters

  • BUS: bus number
  • ID: the ID of the Slack unit it replaces (default "1")
  • rec: the recording, a PlaybackRecording: samples t (s), v (pu), theta (rad) and breaks (s), interpolated by a not-a-knot cubic spline in each piece between breaks
  • piece: the piece of the recording (between breaks) the playback is on; the problem sets it at the start and the breaks advance it
  • status: true when in service

Equations

  • 0 = v - V(t), 0 = θ - Θ(t) (the bus voltage is the recorded one)
  • p and q enter the bus power balance as injections

Variables

  • Algebraic: p, q (the active and reactive power injected into the bus, pu on the system base); they start at the power of the replaced Slack unit in the power flow
  • External: v, theta (the bus voltage)

Breaks

breaks are the times where the recording is discontinuous (a fault applied or cleared). The interpolant restarts at each, and the simulation stops there: the step before ends on the value before the break, a reinitialization of the algebraic variables takes the value after it. They are the playback's only events.

The start

At tspan[1] the power flow's voltage at the bus must be the recording's (after a break at tspan[1]), to the power flow's residual: set the Slack's vs and the bus's va to playback_voltage(pb, tspan[1]). The problem refuses a start that differs, and a tspan outside the recording.

The model has no parameters of its own, and runs on the CPU only.

PowerfulTDS.PlaybackRecording — Type
PlaybackRecording

The recorded voltage of a VoltagePlayback: samples t (s), v (pu) and theta (rad), cut at the breaks into pieces, each interpolated on its own by a not-a-knot cubic spline (C²), held as the slopes dv, dtheta of its cubic Hermite segments at the samples. Piece k holds the samples first[k]:last[k]; outside its samples (up to the breaks around it) a piece continues its end segment. Read-only once built.

source
PowerfulTDS.PlaybackRecording — Method
PlaybackRecording(t, v, theta, breaks; name) -> PlaybackRecording

Check a recording and build its interpolant. name names the instance in the errors.

t is strictly increasing, except that a break time may appear twice in a row: its first sample is the value just before the break (left limit), its second the value just after (right limit). A break time that is not a sample time cuts between the samples around it, and each side continues its end segment to the break. Errors (naming the instance) for: series of unequal lengths, times that do not increase, a break time sampled once (which side it belongs to is not known), breaks that do not increase or are not inside the recording, a piece with fewer than two samples, and non-finite samples.

Faults

PowerfulTDS.Fault — Type
mutable struct Fault{Tv} <: AbstractModel

Three-phase fault model for time-domain simulation.

Represents a 3-phase-to-ground fault as a shunt admittance to ground. The fault absorbs reactive power (large negative susceptance) to cause voltage depression at the faulted bus.

Physics

A 3-phase fault with impedance Zf = Rf + jXf has admittance:

  • Yf = 1/Zf = Gf + jBf
  • Gf = Rf / (Rf² + Xf²)
  • Bf = -Xf / (Rf² + Xf²)

Power consumed by fault (ANDES convention, positive = consumption):

  • P = Gf x V²
  • Q = -Bf x V² (negative Bf → positive Q → absorbs reactive power)

For a bolted fault (Zf → 0), the fault path is predominantly inductive, so we use Gf ≈ 0 and Bf << 0 (large negative susceptance).

Fields

  • i::Int32: Bus number where fault occurs

  • id::InlineStrings.String3: Fault identifier (e.g., "F1", "1")

  • rf::Any: Fault resistance in per-unit on system base

  • xf::Any: Fault reactance in per-unit on system base (small positive → large negative Bf)

  • status::Bool: Fault status: false = cleared (off), true = applied (on)

Usage

# Create fault programmatically (not from RAW file)
fault = Fault(i=10, id="F1", rf=0.0, xf=0.0001)  # Near-bolted fault at bus 10

# Add to system
push!(sys.models.Fault, fault)

# Apply/clear via events
events = [
    FieldModification(1.0, :Fault, (Int32(10), String3("F1")), :status, :set, 1.0),
    FieldModification(1.1, :Fault, (Int32(10), String3("F1")), :status, :set, 0.0),
]

DYR Parsing

PowerfulTDS.create_model_links_for_type — Method
create_model_links_for_type(model_type, dyr_data, sys_pf) -> ModelLinks

Create links between DYR instances and power flow models for a specific model type.

This is similar to create_model_links() but works with raw DYR data (StructVector) before model construction, enabling us to inherit data during parsing.

Arguments

  • model_type::Type - Dynamic model type (e.g., GENCLS)
  • dyr_data::StructVector - Raw DYR data from PowerDynData
  • sys_pf::SystemModel - Power flow system

PowerfulTDS.parse_dynamics — Method
parse_dynamics(dyr_file, sys_pf) -> NamedTuple

Parse PSSE DYR file and return dynamic model parameters.

Two-phase parsing:

  1. Phase 1: Parse models that REPLACE power flow models (generators)
    • Links to PV/Slack in syspf via `getreplacement_map`
  2. Phase 2: Parse models that CONTROL dynamic models (governors, exciters)
    • Links to Phase 1 results via get_controlled_group

Arguments

  • dyr_file::String - Path to PSSE DYR file
  • sys_pf::SystemModel - Power flow system (must contain PV/Slack models)

Returns

NamedTuple with parsed dynamic models (GENCLS, TGOV1, etc.)

Example

dyn = parse_dynamics("case.dyr", sys)
prob = TDSProblem(setup_tds(sol, dyn); tspan=(0.0, 10.0))
