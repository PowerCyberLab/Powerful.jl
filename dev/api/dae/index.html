Core: DAE and Addressing (PowerfulCore)

DAE vectors, address management, indexing and residual evaluation. These names are defined in PowerfulCore.DAEInfra and exported by PowerfulCore. Jacobians and the Newton engine are on Jacobians and Newton; time series solutions and injection recording on Time Series and Injection Recording.

Module

PowerfulCore.DAEInfra — Module

DAEInfra module - Differential-Algebraic Equation infrastructure for Powerful.jl

This module provides the core DAE data structures and operations:

  • Address management for mapping model variables to DAE vectors
  • External-to-internal index conversion
  • DAE vector storage (variables and residuals)
  • Gather/scatter kernels for efficient data movement
  • Residual workspace for model evaluation

DAE Vectors

PowerfulCore.DAEInfra.DAE — Type
DAE{AT}

Paired vectors for DAE/algebraic systems: variables and their residuals.

In power flow (purely algebraic): This holds the current operating point during Newton iteration. The goal is to find y such that g(y) = 0. Differential fields (n, x, f) are unused (n=0, empty vectors).

In time-domain simulation (differential-algebraic): This holds both differential states (x, f) and algebraic variables (y, g). The system is M dx/dt = f(x,y), 0 = g(x,y), where M is the mass matrix.

Type Parameters

  • AT: Array type (Vector{T} for CPU, CuVector{T} for GPU)

Fields

  • m: Number of algebraic variables and residuals
  • y: Algebraic variable vector (unknowns to solve for)
  • g: Algebraic residual vector (equation evaluations, should be zero at solution)
  • n: Number of differential states and residuals (0 for power flow)
  • x: Differential state vector (empty for power flow)
  • f: Differential residual vector (dx/dt evaluations, empty for power flow)

Example

# Power flow (algebraic only, CPU default)
dae = DAE(am)  # Float64, Vector by default
set_algebraic_guess!(dae.y, am, sys, PowerInjection())  # optional initial guess

# Power flow (GPU)
dae = DAE(am; array_type=CuArray)

# Time-domain simulation (differential-algebraic)
dae = DAE(am; allocate_differential=true)

PowerfulCore.DAEInfra.remap_addresses! — Method
remap_addresses!(am::AddressManager, perm::Vector{Int})

Remap the algebraic addresses in-place using the permutation perm (e.g. an AMD ordering of the algebraic Jacobian ∂g/∂y): new address k holds old address perm[k].

perm permutes the algebraic space only. AlgebVar (the y vector) and AlgebRes (the g vector) are square and receive the same permutation (a symmetric reordering of ∂g/∂y). StateVar, StateRes and ObservableVar are separate address spaces (the x, f and observable vectors) and keep their addresses; perm is not defined on them.

PowerfulCore.DAEInfra.retrieve_addresses — Method

Retrieve addresses for external variables and equations for a model.

Uses unified refkey-based lookup into `foreignrefs. All terminal references (both direct model references and group references) are keyed by theirnormalizerefkey(terminal.ref_key)` value.

Reference Types

  1. Homogeneous references: All instances target same model type (e.g., PQ → Bus)
    • GroupLinkRef with uniform target_type
    • Fast path: direct index into source addresses
  2. Heterogeneous references: Instances target different model types (e.g., TGOV1 → GENCLS/GENROU)
    • GroupLinkRef with varying target_type
    • Requires per-instance lookup with group name resolution

Arguments

  • am::AddressManager - Address manager with allocated addresses
  • metadata::ModelMetadata - Metadata for the model requesting addresses
  • models::NamedTuple - All models in the system
  • foreign_refs - Group references from IndexOrder (required for external vars)

PowerfulCore.DAEInfra.build_terminal_refs — Method
build_terminal_refs(model, key_indices_dict, models) -> Dict{GroupRefKey, GroupLinkRef}

Build foreign refs from model TERMINALS (unified approach).

This is the single source of truth for connectivity. Terminals define how models connect to other models or groups. This function builds GroupLinkRef for each terminal, supporting both direct model references and group references.

Key Format (Unified)

All references are keyed by normalize_ref_key(terminal.ref_key), regardless of whether the terminal references a group or a direct model. This provides a consistent lookup pattern: foreign_refs[model_name][normalize_ref_key(ref_key)].

Determining Group vs Direct

  • Group references produce heterogeneous GroupLinkRef (target_type is Vector{Symbol})
  • Direct references produce homogeneous GroupLinkRef (all target_type entries are same)

Use is_heterogeneous(link_ref) to distinguish after lookup.

Arguments

  • model: StructArray of model instances
  • key_indices_dict: Global key → index maps for all models
  • models: NamedTuple of all models (for group reference resolution)

Returns

Dictionary mapping normalized ref_key to GroupLinkRef

Example

# PQ connects to Bus via Terminal(:Bus, :i)
# Result: Dict(:i => GroupLinkRef(:Bus, [1, 2, 3, ...]))

# GENCLS connects to bus_group via Terminal(:bus_group, :BUS)
# Result: Dict(:BUS => GroupLinkRef([:Bus, :Bus, ...], [1, 2, ...]))

# TGOV1 connects to generators via Terminal(:generators, [:BUS, :ID])
# Result: Dict((:BUS, :ID) => GroupLinkRef([:GENCLS, :GENROU, ...], [1, 1, ...]))

Residual Buffers

PowerfulCore.DAEInfra.ResidualBuffers — Type
ResidualBuffers{T, AT, MaskT, VarAddrs, VarVals, ResAddrs, ResVals}

Pre-allocated workspace for a single model type's residual calculation.

Uses NamedTuples for type-stable access to variable and residual arrays. All memory is allocated during construction - zero allocation during calculation.

Type Parameters

  • T: Float type (Float64, Float32, etc.)
  • AT: Array type for data storage (Vector{T} for CPU, CuVector{T} for GPU)
  • VarAddrs: NamedTuple type for variable addresses
  • VarVals: NamedTuple type for variable values
  • ResAddrs: NamedTuple type for residual addresses
  • ResVals: NamedTuple type for residual values
  • System: SystemConfig type

Fields

  • var_addrs: NamedTuple mapping variable names to address vectors (always CPU)
  • var_vals: NamedTuple mapping variable names to value vectors (can be CPU/GPU)
  • res_addrs: NamedTuple mapping residual names to address vectors (always CPU)
  • res_vals: NamedTuple mapping residual names to value vectors (can be CPU/GPU)
  • setpoints: NamedTuple of initialization setpoints (reference, not typed for simplicity)
  • automata: the AutomatonState of the model's automata (modes, discrete quantities, memory and the values of its guards), empty for a model without automata; the kernels read its discrete quantities and memory
  • system: SystemConfig of the system the workspace belongs to (sys.settings)
  • n_instances: Number of model instances

Note on active_mask

The active_mask (which instances are in-service) is NOT stored in this struct. Instead, it is passed as a parameter to scatter_residuals! and calc_residuals!. This enables parallel ACCC with thread-local status arrays - each thread can have its own isolated status without affecting others.

Setpoints

For dynamic models (e.g., GENCLS), setpoints stores initialization setpoints used in holding equations (e.g., Pm0, Eq0). These are passed by reference from the TDS initialization result, not copied. For models without setpoints, this is an empty NamedTuple ().

System settings

ws.system holds the system-wide settings of the system (sys.settings), type-stable.

Example

For a PQ load model on CPU (no setpoints):

ws = ResidualBuffers{Float64, Vector{Float64}, ...}(...)
v_values = ws.var_vals.v  # Vector{Float64}

ResidualBuffers(ws::ResidualBuffers, ::Type{T}; setpoints_at_values = false) -> ResidualBuffers

A copy of ws in element type T: every number it holds (variables, residuals, setpoints, and the discrete quantities, memory and values of its automata) in buffers of its own of element type T at the values of ws; its addresses, automaton modes and configuration shared. PowerfulCore.DAEInfra.build_res_scatter_tuple — Method
build_res_scatter_tuple(res_addrs, res_vals, metadata; skip=Returns(false)) -> Tuple

Build pre-computed tuple for zero-allocation residual scattering in TDS.

Returns a tuple where each element is (addrs, vals, is_diff::Bool, mode::Symbol):

  • addrs: Address vector for this residual
  • vals: Value vector for this residual
  • is_diff: true if differential residual (scatter to f), false if algebraic (scatter to g)
  • mode: Scatter mode (:private, :add, or :set)

This eliminates runtime Symbol lookup via getfield(ws.res_addrs, res_name).

Arguments

  • res_addrs: NamedTuple of residual address vectors
  • res_vals: NamedTuple of residual value vectors
  • metadata: ModelMetadata with residual specifications
  • skip: Optional predicate function (res_meta) -> Bool. Residuals for which skip(res_meta) returns true are excluded from the tuple. Default: include all.

Example

# Standard scatter tuple (all residuals)

# Filtered scatter tuple (skip bus injections for Y-bus formulation)
internal_tup = build_res_scatter_tuple(res_addrs, res_vals, metadata;
    skip = res -> res.source_model === :bus_group)

Note: Uses explicit loop instead of map to reduce method compilations (~78% fewer gather/scatter compilations), though JIT time improvement is negligible due to NamedTuple type specialization being the dominant cost.

PowerfulCore.DAEInfra.AffineRelation — Type
AffineRelation{T<:Number}

The affine form of a governed state's right side (round 19a, Phase D): constant[i] + sum_k coefficients[k, i] * var_vals[vars[k]][i], SPARSE over vars, the variables (indices among the keys of ws.var_vals) the relation actually reads – check_governed's own admissibility trace (reads.pattern, PowerfulTDS governed_states.jl) already knows this exactly, so the hot path (enforce_governed_affine!) need not scan every variable of the model's workspace to find the handful (often one or two) a relation's right side actually names. Computed once per parameter set, not per residual evaluation (refresh_affine_governed!), in the workspace's own element type T, so that a parameter carried as a Dual number leaves its partials in the coefficients themselves, not only in the variables they multiply – the same requirement AutomatonState's own memory/values fields hold for per-T recomputation (see its own docstring). vars and coefficients are reassigned (not merely mutated elementwise) by refresh_affine_governed!, since a retrace can in principle change which variables are read (an admissible right side's kernel branching on a parameter, see its own docstring) – hence a mutable struct, so the same AffineRelation object stays referenced from ws.automata.affine across a resize rather than needing the immutable NamedTuple that holds it rebuilt.

PowerfulCore.DAEInfra.AutomatonState — Type
AutomatonState{Modes, Discrete, Memory, Values, Affine}

The discrete state of every instance of a model with automata:

  • modes: automaton name => the mode of each instance, an index into the automaton's modes;
  • discrete: discrete quantity => its value for each instance, what the mode holds;
  • memory: memory name => its value for each instance;
  • values: value name => its value for each instance, as the model's calc_automaton_values! last computed it (atoms, guards, holds, sets and memory starts, see automaton_values);
  • affine: value name => the affine form of a governed-state relation by that value (AffineRelation, round 19a Phase D), empty for a model that governs no state.

The simulation sets the modes, discrete quantities and memory at its start and where transitions fire; before a start they are 0 (modes) and NaN (values), so that a residual evaluated before one is not silently computed with a default. The residual kernels read discrete and memory; nothing else writes them.

The contract of the kernels. calc_residuals! computes the rates and residuals of instance i, and calc_automaton_values! its values, from the variables, parameters, setpoints, external parameters and instance i's own entries of discrete and memory only: never from another instance's (a rate r[1] * r[2] of two instances' discrete quantities breaks it). With the state fixed, a switch of one instance then changes that instance's rates alone, and switches of several instances at one instant combine without interacting, which an augmentation that integrates sensitivities through them relies on; and at the same state a switch of one instance changes that instance's values alone, so that a settle considers only the instances that switched. Every simulation checks the contract for calc_automaton_values! when it is set up, from the trace of the values with the discrete quantities and memory of each instance as inputs of their own (PowerfulTDS, trace_value_reads), and, for a model whose values break it, warns and settles every instance of the model in every round (correct, slower). Where switches of several instances fire at one instant, a parameter-sensitivity augmentation checks the contract on the rows with mass (each switch alone from the discrete state before the instant, and each switch left out from the state after it, changes its own instance's rates only) and refuses a kernel that breaks it there; an interaction that shows at neither end remains the kernel author's responsibility.

PowerfulCore.DAEInfra.calc_automaton_values! — Method
calc_automaton_values!(ws::ResidualBuffers{T, AT}, model::StructArray, external::NamedTuple,
                       formulation, t)

Compute, for every instance of model, each value its automata name (see automaton_values: the atoms a - b of its conditions, its crossing guards, and the holds, sets and memory starts that are not numbers) into ws.automata.values, from the variables gathered into ws.var_vals at time t, its parameters, setpoints, external parameters and the discrete quantities and memory of ws.automata: the inputs its calc_residuals! reads.

A model that declares automata implements it in the kernel pattern of calc_residuals! (a data adapter calling a kernel that dispatches on AT). Out-of-service instances are computed as the others; the simulation does not fire their transitions. Which variables it reads must not depend on the variables, the time, the discrete quantities and memory (no branch on them): the simulation traces the kernel for the variables it reads, and gathers only those (evaluate_automaton_values!). It may branch on a real parameter or a setpoint: it is traced at their values then, and again where an event changes them, gathering every variable (PowerfulTDS trace_value_reads).

Both this kernel and the model's calc_residuals! follow the contract of AutomatonState: what belongs to instance i reads instance i's own discrete quantities and memory only.

PowerfulCore.DAEInfra.enforce_governed! — Method
enforce_governed!(ws, metadata::ModelMetadata, t)

A governed state is its relation's value at every point a reader decides on, not whatever the integration carries between the discrete writes that land it there exactly (_enter_governed!, PowerfulTDS governed_states.jl): for every state a mode of metadata.automata governs (Mode.states), at every instance whose automaton ws.automata.modes currently holds in that mode, overwrite the state's column of ws.var_vals with the mode's right side – a number, or the matching, already-computed column of ws.automata.values. Every reader of ws.var_vals downstream of this call (a value, a guard, a residual) then sees the relation, not the drifted state.

Zero cost where no automaton of metadata governs a state (governs_states): nothing is read or written. The branch this function makes, per instance, is on ws.automata.modes[a.name][i], a concrete Int – automaton-state data, never a Dual or a tracer quantity – so tracing through it (PowerfulTDS trace_value_reads) never refuses it as a branch on a variable.

This is a view-level correction only: it never writes x/y, the DAE vectors the integrator advances, so it never itself makes the automata settle again; what is actually stored there is corrected only at the discrete instants _enter_governed! already writes (entry, event repair, and the farewell write at a mode's exit), not here.

PowerfulCore.DAEInfra.enforce_governed_affine! — Method
enforce_governed_affine!(ws, metadata)

The residual path's substitution (round 19a, Phase D): for every state a mode of metadata.automata governs, at every instance whose automaton ws.automata.modes currently holds in that mode, overwrite the state's column of ws.var_vals with its relation's affine form (AffineRelation, refresh_affine_governed!) – a dot product over relation.vars, the SPARSE set of variables the relation actually reads (often one or two, never every variable the model gathers, regardless of how large the model's own variable set is) – instead of calling calc_automaton_values! to get a fresh value. calc_residuals! (what this feeds, in _gather_and_calc!) never reads ws.automata.values, only ws.var_vals, so there is no self-reference to resolve the way evaluate_automaton_values!'s two-pass shape must for the values/condition path: one pass over the governed states suffices here, and it costs one multiply-add per variable the relation reads instead of a whole kernel invocation.

Zero cost where no automaton of metadata governs a state, or while the automata are suspended (ws.automata.suspended[], the same guard enforce_governed! itself makes, for the same reason: a guard deciding a release during a fixed-time event's first settle round must read the retained state, not a value this substitution would already have put on the relation). Where used, this REPLACES the calc_automaton_values! call the residual path used to pay (see the private round 19a design notes): the values/condition path (evaluate_automaton_values!) is untouched and keeps calling the kernel twice, where exactness (not speed) is required.

PowerfulCore.DAEInfra.evaluate_automaton_values! — Method
evaluate_automaton_values!(ws, gather::Tuple, model, external, x, y, formulation, t, metadata)

Gather the variables of gather from x and y into ws and compute the values of the automata of model at time t into ws.automata.values (calc_automaton_values!). gather holds entries of ws.var_gather_tuple (variable_gather): every variable the model's calc_automaton_values! reads, or more. The variables outside it keep whatever ws.var_vals held, which the kernel then must not read; the simulation gathers exactly those its trace of the kernel found it reads (PowerfulTDS, trace_value_reads).

Where metadata.automata governs a state (governs_states), the kernel is run twice: once to get a fresh relation for every value that is not a mirror of the governed state itself (this first pass never reads the governed state, check_governed's own admissibility proof), then enforce_governed! substitutes the governed state's column with that relation, then the kernel is run again so that every value that is a function of the governed state (e.g. a position atom comparing it with its own bound) reads the enforced value, not the first pass's stale one. This is _enter_governed!'s own "write, then re-evaluate the values" shape, applied on every call instead of only at a discrete write. For a model that governs no state this is the original, single call.

PowerfulCore.DAEInfra.refresh_affine_governed! — Method
refresh_affine_governed!(ws::ResidualBuffers{T}, model, external, formulation, read_vars) where T

Recompute the affine form (AffineRelation) of every governed-state relation of metadata.automata, in ws's own element type T: once at the current (zeroed) point for the constant term, then once more per variable any relation reads (the union of read_vars's values), shifted by one(T) with every other variable held at zero, for that variable's coefficient in every relation it affects – exact, not a finite-difference approximation, because check_governed has already proven every such relation affine (degree at most 1) in the variables it reads, with parameter-dependent coefficients only (PowerfulTDS governed_states.jl). ws.var_vals is saved before and restored after (this never leaves the workspace's variables at the zeroed probe point); t is not needed, since the same admissibility proof refuses a relation that reads the time.

read_vars[ref] (a Dict{Symbol, Vector{Int}}, one entry per key of ws.automata.affine): the variables (indices among the keys of ws.var_vals) relation ref actually reads, from check_governed's own trace of the model's values (reads.pattern, PowerfulTDS governed_states.jl _value_read_variables) – reused, not retraced here. Each relation's vars/coefficients are REASSIGNED (not merely overwritten elementwise) to this sparsity, since AffineRelation is a mutable struct precisely so an earlier, differently-sized relation can be replaced without rebuilding the NamedTuple (ws.automata.affine) that holds it: the hot path (enforce_governed_affine!) then sums over length(vars) terms, typically one or two, never over every variable of the model's workspace, regardless of how many other variables the model gathers.

Zero cost (and a no-op) where ws.automata.affine is empty (a model that governs no state, or one whose every right side is a plain number). Called once when Governed is built, and again whenever a fixed-time event retraces a model's governed states (Governed.recheck!, the same trigger that already re-checks admissibility) – never in the residual hot path itself (enforce_governed_affine! reads the cache there instead of recomputing it).
