Power Flow Results and Reports (PowerfulPF)

Access to solution variables and residuals, and tabular and text reports.

Variable and Residual Accessors

PowerfulPF.bus_voltages — Method
bus_voltages(sol::PowerFlowSolution) -> (v, theta)

Voltage magnitude (pu) and angle (rad) of every bus, in internal order, whatever the formulation of the solution: PowerInjection solves them directly, CurrentInjection solves the rectangular components (v = |v_r + j·v_i|), and DCPowerFlow solves the angles, with the magnitudes at the case voltages vm that its load and shunt models use.

Observations and reports read bus voltages through this function, so they are defined for every formulation.

source
PowerfulPF.generator_power — Method
generator_power(sol::PowerFlowSolution, model::Symbol) -> (p, q)

Active and reactive power (pu) that each generator of model (:PV or :Slack) supplies. The power flow solves the total generator power at each bus: the balance of every other contribution to the bus power equations (get_generator_residuals). In CurrentInjection the bus equations are current balances, and the slack bus rows belong to the slack equations, so the power balances of the PowerInjection form are evaluated at the solved voltages instead.

The units at a bus share its total:

  • A PV unit supplies its scheduled active power pg. Slack units share the active power balance of their bus in proportion to their MVA base mbase, as units with equal per-unit droop do.
  • All units at a bus share its reactive power in proportion to rmpct, the percent of the total Mvar each unit supplies.

An out-of-service unit supplies nothing. DCPowerFlow has no reactive power: q is nothing.

PowerfulPF.get_all_vars — Method
get_all_vars(prob::ACPowerFlowProblem, y::AbstractVector, model::Symbol, var::Symbol) -> Vector

Get all values for a variable across all instances (in internal order).

Returns a view into the state vector, not a copy.

Examples

# Get all bus voltages from solution
prob = ACPowerFlowProblem(sys, PowerInjection())
sol = solve(prob, RobustNR())
voltages = get_all_vars(prob, sol.dae.y, :Bus, :v)

# Get all bus voltage angles
angles = get_all_vars(prob, sol.dae.y, :Bus, :theta)

PowerfulPF.get_var — Method
get_var(prob::ACPowerFlowProblem, y::AbstractVector, model::Symbol, var::Symbol, ext_key) -> T

Get variable value using external key (e.g., bus number).

Generic function that works for any variable in any model by combining:

  1. IndexOrder: external key → internal array index
  2. AddressManager: model/variable → DAE addresses
  3. State vector: addresses → actual values

Arguments

  • prob::ACPowerFlowProblem: Power flow problem (contains sys and address_manager)
  • y::AbstractVector: State vector (from solution, workspace, or custom)
  • model::Symbol: Model name (:Bus, :PQ, :PV, etc.)
  • var::Symbol: Variable name (:v, :theta, :p, etc.)
  • ext_key: External key for lookup (bus number, or tuple for composite keys)

Returns

  • Variable value (type matches y element type)

Examples

# After solving - query solution
prob = ACPowerFlowProblem(sys, PowerInjection())
sol = solve(prob, RobustNR())
v = get_var(prob, sol.dae.y, :Bus, :v, (4001,))

# During iteration - query workspace state
workspace = setup_powerflow_newton(prob)
v_iter = get_var(prob, workspace.cache.iter_dae.y, :Bus, :v, (4001,))

# Query trial point during line search
v_trial = get_var(prob, workspace.y_trial, :Bus, :v, (4001,))

# Bus voltage angle
theta = get_var(prob, sol.dae.y, :Bus, :theta, (4001,))

Only variables (entries of y) are accessible. Residual names such as a load's :p or a branch's :p_i raise an error; injections and flows are reported by collect_model_table.

Errors

  • If prob.sys.order is nothing: Error (IndexOrder required)
  • If model or external key not found: error from get_index_by_key
  • If model/variable not found: Error from AddressManager

PowerfulPF.get_var_by_index — Method
get_var_by_index(prob::ACPowerFlowProblem, y::AbstractVector, model::Symbol, var::Symbol, idx::Int) -> T

Get variable value using internal array index (1-based indexing).

Faster than get_var() since it skips external→internal mapping. Use when you already have internal indices.

Arguments

  • prob::ACPowerFlowProblem: Power flow problem
  • y::AbstractVector: State vector
  • model::Symbol: Model name
  • var::Symbol: Variable name
  • idx::Int: Internal array index (1-based)

Example

# Direct access by internal index (no external key lookup)
prob = ACPowerFlowProblem(sys, PowerInjection())
sol = solve(prob, RobustNR())
v = get_var_by_index(prob, sol.dae.y, :Bus, :v, 1)  # First bus in internal ordering

PowerfulPF.ColumnPreferences — Type
ColumnPreferences

Configuration for column selection and naming.

Fields

  • use_descriptions::Bool: Use ModelParam.description vs. field name
  • include_units::Bool: Append "(MW)", "(pu)" to column names
  • column_style::Symbol: Naming style - :compact (pfrom), :short (pfrom (MW)), :verbose (full description)
  • include_id::Bool: Include instance ID column
  • include_vars::Union{Nothing, Vector{Symbol}}: If set, only include these variables
  • exclude_vars::Vector{Symbol}: Exclude these variables
  • include_params::Bool: Include model parameters
  • exclude_params::Vector{Symbol}: Exclude these parameters

PowerfulPF.ReportConfig — Type
ReportConfig

Complete configuration for power flow report generation.

Fields

  • units::UnitPreferences: Unit conversion preferences
  • formatting::FormattingPreferences: Value formatting preferences
  • columns::ColumnPreferences: Column selection and naming

Examples

# Default configuration
config = ReportConfig()

# Customize units only
config = ReportConfig(units=UnitPreferences(voltage=:kv, angle=:rad))

# Customize multiple aspects
config = ReportConfig(
    units = UnitPreferences(voltage=:kv, power=:pu),
    formatting = FormattingPreferences(float_precision=6),
    columns = ColumnPreferences(exclude_vars=[:internal_state])
)

# Use preset configurations
config = AllPerUnit
config = AllPhysical

PowerfulPF.UnitPreferences — Type
UnitPreferences

Configuration for unit conversions in reports.

Fields

  • power::Symbol: Power units - :physical (MW/MVAR) or :pu
  • voltage::Symbol: Voltage units - :pu (default) or :kv
  • angle::Symbol: Angle units - :deg (default) or :rad
  • impedance::Symbol: Impedance units - :pu or :ohm
  • base_mva::Float64: System base power in MVA (default: 100.0)

Examples

# Default: physical power, pu voltage, degrees
UnitPreferences()

# All physical units
UnitPreferences(voltage=:kv, power=:physical)

# All per-unit
UnitPreferences(power=:pu, voltage=:pu, angle=:rad)

PowerfulPF.collect_model_table — Method
collect_model_table(sol::MultiIslandSolution, model_name::Symbol; config=Default)

Collect model data from a multi-island solution, merging results from all islands.

Returns a unified table containing data from all islands. Instances are included from all islands based on their external keys.

Note: MultiIslandSolution is defined in src/solvers/solution_types.jl. This function handles the I/O-specific concern of merging data tables across islands.

Arguments

  • sol::MultiIslandSolution: Multi-island power flow solution
  • model_name::Symbol: Name of model type (e.g., :Bus, :Branch)
  • config::ReportConfig: Configuration for units, formatting, and columns

Example

sol = solve(ACPowerFlowProblem(sys), RobustNR())  # May return MultiIslandSolution
bus_data = collect_model_table(sol, :Bus)
df = DataFrame(bus_data)

PowerfulPF.get_default_outputs — Method
get_default_outputs(model_type::Type{<:AbstractModel}) -> Vector{Symbol}

PowerfulPF.print_model_table — Method
print_model_table(sol, model_name::Symbol; config=Default, kwargs...)

Pretty-print model data as formatted table using Pretty Tables.jl.

This function activates the config.formatting preferences (floatprecision, etc.) which are otherwise unused by `collectmodel_table()`.

Arguments

  • sol: PowerFlowSolution or MultiIslandSolution
  • model_name::Symbol: Model to print (e.g., :Bus, :Branch)
  • config::ReportConfig: Report configuration
  • kwargs...: Passed to PrettyTables.jl

Examples

# Terminal output (default)
print_model_table(sol, :Bus)

# Customized precision using config
config = ReportConfig(formatting = FormattingPreferences(float_precision = 2))
print_model_table(sol, :Bus; config=config)

# Compact format
print_model_table(sol, :Branch; config=Compact)

PowerfulPF.PowerFlowReport — Type
PowerFlowReport

Structured power flow report data, format-agnostic.

Contains all information needed to generate a report in any format (text, markdown, JSON, etc.). The report captures system metadata, convergence information, and model result tables. It covers every model of the system that has outputs (see get_default_outputs).

Fields

  • counts::OrderedDict{Symbol, Int}: Instances of each reported model, in presentation order
  • converged::Bool: Whether the power flow converged
  • iterations::Int: Number of solver iterations
  • final_residual::Float64: Final residual norm (infinity norm)
  • sections::OrderedDict{Symbol, NamedTuple}: Model data tables in presentation order

Example

# Build report from solution
report = build_powerflow_report(sol, config)

# Render as text
text = format_text(report)
println(text)

# Future: other formats
# markdown = format_markdown(report)
# json = format_json(report)

PowerfulPF.build_powerflow_report — Method
build_powerflow_report(sol, config::ReportConfig) -> PowerFlowReport

Build a structured power flow report from a solution.

Extracts system metadata, convergence statistics, and model result tables according to the provided configuration. The resulting report is format-agnostic and can be rendered in multiple ways.

Arguments

  • sol: Power flow solution from solve(): a PowerFlowSolution in any formulation, or a MultiIslandSolution (its tables merge the islands, and it converged when every island did)
  • config::ReportConfig: Report configuration (units, formatting, columns)

Returns

PowerFlowReport containing all report data

Example

prob = ACPowerFlowProblem(sys)
sol = solve(prob, RobustNR())

# Build report with custom config
config = ReportConfig(units=UnitPreferences(voltage=:kv))
report = build_powerflow_report(sol, config)

# Render as text
text = format_text(report)
source
PowerfulPF.format_text — Method
format_text(report::PowerFlowReport; config=Default, backend=:text) -> String

Render a PowerFlowReport in various formats using PrettyTables.jl.

Generates a complete power flow analysis report with:

  • System summary (instances of each reported model)
  • Convergence information (status, iterations, residual)
  • Model result tables (buses, generators, loads, shunts, branches, transformers)

Arguments

  • report::PowerFlowReport: Report data structure
  • config::ReportConfig: Report configuration (for formatting precision)
  • backend::Symbol: Output format (:text, :markdown, :html, :latex)

Returns

Formatted string suitable for console or file output

Example

config = ReportConfig(formatting=FormattingPreferences(float_precision=2))
report = build_powerflow_report(sol, config)

# Text output (default)
text = format_text(report; config=config)
println(text)

# Markdown output (for documentation)
md = format_text(report; config=config, backend=:markdown)
write("report.md", md)

# HTML output (for web reports)
html = format_text(report; config=config, backend=:html)
write("report.html", html)
